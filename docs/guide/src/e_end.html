STEP 710분

정답값으로 검증하기

AI가 "완성했습니다"라고 해도 숫자로 확인합니다. 화면이 그럴듯해도 숫자는 틀릴 수 있습니다.

이렇게 말고

AI가 "완성했습니다"라고 하면 믿고 바로 공유하기

틀린 숫자는 눈으로는 안 보입니다.

이렇게

정답값과 화면 숫자를 한 표로 대조하고, 엑셀에서 3개를 직접 계산하기

틀린 곳은 표에서는 바로 보입니다.
AI 코딩 도구에 붙여넣기
정답값 대조표를 만들어 주세요.
1) 가상 데이터로 미리 정한 정답값 5개(평균, 건수, 등급별 개수 등)와 화면 숫자를 표로 대조하세요: 항목 / 기대값 / 실제값 / 일치 여부
2) 경계값 테스트(90.0, 89.9 등)를 실행하고 결과를 보여 주세요
3) 필터를 바꿔도 모든 카드가 같은 목록으로 계산되는지 확인하세요
일치하지 않는 것은 고치기 전에 원인 후보를 먼저 알려 주세요.
성공하면표의 "일치" 칸이 모두 ✓입니다. 틀린 줄이 있으면 AI가 원인 후보와 함께 알려 줍니다(아래 예).
항목기대값(정답값)실제값일치
협력사 수1,2481,248✓
평균 점수82.982.9✓
A 등급 개수211211✓
90.0점의 등급 / 89.9점의 등급A / BA / B✓
D 등급 개수1716✗ 원인 후보: 60.0점 경계값 처리
사람이 하는 일화면의 숫자 3개(평균·건수·A 비율)를 엑셀에서 직접 계산해 맞춰 봅니다. 하나라도 다르거나 점검 경고가 있으면 공유하지 않습니다.
정답값 없이 만들었다면지금 만드세요. 가상 데이터로 평균과 개수를 한 번 직접 계산해 적어 두면 됩니다.
검토는 새 대화에서 한 번 더만든 AI가 스스로 "맞다"고 하면 같은 실수를 되풀이합니다. 새 대화에 가상 대조표와 규칙표만 붙여 넣고 "틀릴 수 있는 곳 3개"를 찾게 하세요.

용어: 점검 리포트는 데이터를 읽는 도구가 건수·경고를 모아 알려 주는 결과입니다.

STEP 85분

안전하게 공유하기

화면만 공유하고 데이터는 지킵니다. 잘못 올린 파일은 거두기 어렵습니다.

이렇게 말고

엑셀과 데이터 파일을 GitHub 같은 저장소나 공유 폴더에 올리기

지워도 이력에 남습니다. 사내 저장소도 같습니다.

이렇게

화면 파일만 공유하고, 데이터 파일은 저장소에서 제외 + 커밋 전 점검

저장소 접근 권한과 데이터 접근 권한은 다릅니다.
AI 코딩 도구에 붙여넣기
데이터 파일이 저장소에 올라가지 않게 해 주세요.
1) .gitignore에 데이터 폴더·엑셀·CSV·생성된 data 파일 추가
2) 커밋 전에 데이터 파일이 섞였는지 검사해 막는 스크립트(훅) 만들기
3) 엑셀 파일을 일부러 하나 추가해 보고, 정말 커밋이 막히는지 결과 보여 주기
저장소에 올릴 것(코드·문서)과 올리지 않을 것(데이터)을 표로 정리해 주세요.
성공하면엑셀을 추가한 커밋이 막히고, 막힌 파일 이름과 이유가 보입니다.

공유 방법 3가지 — 고르는 질문: "데이터가 저장소에 올라가도 되는가?"

방법어떻게언제
① 각자 PC에서 열기화면 파일을 받아 본인 엑셀을 넣고 만든 뒤 열기. 데이터가 PC 밖으로 나가지 않습니다.기본값
② 사내 서버·공유 폴더담당자가 만든 화면 폴더를 복사. 접근 제한은 서버에서 합니다.여러 명이 볼 때
③ 사내 GitHub Pages화면 폴더를 발행 전용 브랜치로 공개. 데이터가 함께 올라가므로 정책 확인이 먼저입니다.정책 확인 후에만

밖에서 보려면 접근 제어가 먼저입니다. 회사 데이터는 담당자와 상의 → 응용편(17쪽)

갱신은 이 순서로

교체 → 빌드 → 점검 → 배포 → 확인. 반복되는 순서라 맡길 수 있지만 경고 0건이 아니면 배포하지 않고, 승인은 사람이 합니다. 첫 화면 숫자 3개는 엑셀과 맞춰 본 뒤 공유하세요.

AI 대화 패널(챗)을 대시보드에 넣고 싶다면화면과 열고 닫기만 만들고, 호출 코드(주소·키)는 넣지 마세요. 연결은 별도로 하고 키는 서버에만 둡니다.

응용: 켜 둔 PC로 개인용 대시보드 만들기

나 혼자 보는 대시보드라면 클라우드나 DB 없이 켜 둔 PC 한 대로 시작할 수 있습니다. 처음부터 클라우드·DB에 도전하면 대부분 거기서 막힙니다.

회사 데이터라면 이 쪽의 방법을 쓰지 마세요사내 데이터는 사내 도구·서버(STEP 8의 ①②)에서만 다룹니다. 외부 접속은 정보보안 담당자 승인 없이 만들지 않습니다. [사내 AI 사용 지침 링크 · 담당자]

저는 비개발자이고, 저만 보는 개인용 대시보드를 만들려고 합니다. 아래 원칙과 5단계를 따라 주세요.
원칙
- MVP 우선: 가장 먼저 보고 싶은 핵심 1~2개만 되는 버전부터 만들고 단계별로 넓힙니다.
- AWS·외부 DB 없이, 제 PC에서 항상 켜 두는 로컬 웹 서버로 가볍게 시작합니다.
- 입력(목적+가진 것)과 출력(화면 스케치)이 정해지기 전에는 코드를 쓰지 말고 대화로 좁힙니다.
- 여백·카드 배치·글자·반응형을 우선하고, 구현 뒤 마지막에 디자인 검수를 합니다.
진행: ① 핵심 지표(예: 주문·재고 현황, 관심 주식 지수)와 제 데이터·장비 파악 ② MVP 범위 확정, Step 1·2·3 분할 ③ 제 스케치(또는 글 설명)로 화면 와이어프레임 확정 ④ 제 PC에서 바로 실행되는 대시보드 구현 ⑤ 밖에서도 저만 접속하도록 접근 제어(문지기) 연결 방법을 초보자 눈높이로 안내
제약: 실제 데이터 값(고객명·금액 등)은 묻지 마세요. 데이터 종류와 열 이름만 묻습니다.
지금은 ①만 하세요. 핵심 질문 3~4가지만 먼저 해 주세요.
성공하면AI가 핵심 질문 3~4개만 하고 멈춥니다. 답하면 MVP 범위와 Step 1·2·3이 나옵니다.

지금 상황할 것단계
AI가 만든 화면이 내 질문과 안 맞는다질문을 한 문장부터 다시 정하고, 화면 정의서를 새로 받는다. 처음이라면 질문 1~2개·화면 1장(MVP)부터STEP 1
원하는 배치를 말로 설명하기 어렵다칸에 번호를 붙인 스케치 한 장(또는 글로 쓴 배치)을 함께 준다STEP 2
숫자는 맞는데 화면이 지저분하고 뭘 봐야 할지 모르겠다디자인 기준 7가지로 점검시키고, "핵심 숫자 1개를 크게, 색은 의미 있을 때만"으로 고칠 곳 3개만 지정한다STEP 3
만들 때마다 스타일이 달라진다디자인 값(토큰)을 표로 먼저 정하게 하고 그 값만 쓰게 한다STEP 3

대화가 길어져 AI가 앞 내용을 잊는다PROGRESS.md를 읽히고 새 대화에서 이어간다STEP 6
엑셀 열 이름이 바뀌었다오류가 알려 주는 비슷한 이름을 동의어로 추가하게 한다STEP 6
숫자가 의심스럽거나 화면마다 다르다정답값 대조표 + 엑셀에서 3개 직접 계산, 모든 카드가 같은 목록에서 계산되는지 확인. 새 대화에서 한 번 더 검토STEP 7

끝났는지 확인하기

공유하기 전에 아래를 모두 체크하세요. 하나라도 비어 있으면 해당 STEP으로 돌아갑니다.

  • 질문 2~3개·KPI가 한 장에 있고, 첫 버전(MVP)은 1~2개다 (STEP 1)
  • AI에게 데이터 내용을 붙여넣지 않았다 — 열 이름·가상 값만 (안전망)
  • 원하는 배치를 스케치 한 장(또는 글)으로 AI에게 줬다 (STEP 2)
  • 목업을 보며 3번 이상 고쳤다 (STEP 2~4)
  • 3초 테스트를 통과했다 — 처음 보는 사람이 핵심 숫자와 좋고 나쁨을 말한다 (STEP 3)
  • 규칙표(경계값 포함)와 임시 기준 목록이 있다 (STEP 5)
  • 지시서에 단계·완료 기준·하지 말 것이 있다 (STEP 6)
  • AI 코딩 도구가 단계마다 보고했고 PROGRESS.md가 있다 (STEP 6)
  • 정답값 대조표가 모두 일치한다 (STEP 7)
  • 엑셀에서 직접 계산한 숫자 3개가 화면과 같다 (STEP 7)
  • 만든 AI와 별개로 새 대화에서 한 번 더 검토시켰다 (STEP 7)
  • 데이터 파일이 저장소에 없다 — .gitignore + 커밋 전 점검 (STEP 8)
  • 갱신 순서를 적어 뒀고, 배포 승인은 내가 한다 (STEP 8)
  • 필요한 곳에 "가상 샘플"·"임시 기준" 표시가 있다 (STEP 2·5)
