# 교육용 쇼츠 기획안 — "AI로 대시보드, 처음부터 다시 만들지 않기" (6편)

가이드(`index.html`, 21쪽)를 **45초짜리 쇼츠 6편**으로 줄였습니다. 한 편에 **한 가지 행동**만 남기고, 보고 나서 바로 복사해 쓸 **프롬프트 한 줄**을 줍니다.

## 1. 기본 설정

| 항목 | 내용 |
|---|---|
| 대상 | 코딩을 모르고, AI로 업무용 대시보드를 처음 만들어 보는 사람 |
| 목표 | 시청 후 "AI에게 이렇게 말하면 되는구나"를 하나 가져가기 |
| 형식 | 세로 9:16, 편당 40~50초(60초 넘기지 않기), 총 6편 |
| 구성 | 훅 3초 → 문제 8초 → 해결·시연 25초 → 한 줄 정리 + 프롬프트 7초 → 댓글 질문 |
| 말투 | 쉬운 말. 전문용어는 첫 등장에 한 줄 풀이 (예: "KPI = 핵심 숫자") |
| 자막 | 필수. 소리 없이도 이해되게, 큰 글씨 한 줄 12자 안팎 |
| 화면 | 전부 **가상 데이터**. 가이드의 나쁜/좋은 화면, 스케치, 프롬프트 상자를 그대로 사용 |

## 2. 6편 구성

| 편 | 제목 | 한 가지 행동 | 가이드 쪽 |
|---|---|---|---|
| 1 | "대시보드 만들어줘"가 망하는 이유 | 질문 한 문장부터 정한다 | 2·3·6 |
| 2 | 엑셀을 통째로 붙여넣지 마세요 | 열 이름과 가상 값만 준다 | 5·7 |
| 3 | 말 대신 그림 한 장, 숫자 하나는 크게 | 스케치를 주고 핵심 숫자 1개를 키운다 | 8·9 |
| 4 | 'AI 티' 지우고 "별로야" 대신 이렇게 | 한 번에 3가지만, 순서대로 고친다 | 10·11 |
| 5 | AI가 "완성!"이라 해도 믿지 마세요 | 규칙은 숫자로, 결과는 대조표로 | 12·15 |
| 6 | 오류가 나면, 올리기 전에 | F12 글씨를 AI에게, 데이터는 올리지 않는다 | 16·17 |

### 편 1. "대시보드 만들어줘"가 망하는 이유
- 훅: "AI한테 '대시보드 만들어줘'라고만 하면, 결국 처음부터 다시 하게 됩니다"
- 대본
  - 0~3초 훅
  - 3~11초: 문제는 AI가 아니라 **순서**. 사람이 정하고 → AI가 만들고 → 사람이 숫자로 확인
  - 11~36초: ❌ "매출 대시보드 만들어줘" / ✅ "팀장이 월요일 회의에서 1분 안에 보게 하고 싶습니다" 비교. 첫 버전은 질문 1~2개.
  - 36~45초: 정리 + 프롬프트
- 화면: 입력(사람) → 과정(AI) → 출력(사람) 세 칸 그림, 가이드 2쪽 그대로.
- 프롬프트: `이 질문에 답하는 KPI와 화면만 제안해 줘. 답하지 않는 차트는 넣지 마.`
- 댓글 질문: "내 대시보드가 답해야 할 질문은 뭔가요?"

### 편 2. 엑셀을 통째로 붙여넣지 마세요
- 훅: "엑셀 내용을 AI에 붙여넣으면 되돌릴 수 없습니다"
- 대본: 줄 것(열 이름·형식·규칙·가상 값) vs 주지 않을 것(업체명·금액·개인정보·비밀번호·키) 표 → "값은 가상으로 만들어"로 화면이 완성되는 장면 → 이미 붙여넣었다면 **멈추고 담당자에게 알리기**.
- 화면: 붙여넣기 ❌(빨간 X) / 열 이름만 ✅. 가이드 5·7쪽.
- 프롬프트: `열 이름과 형식만 알려 줄게. 값은 가상으로 만들어 줘.`
- 댓글 질문: "회사에서 AI에 올리면 안 되는 것, 정해져 있나요?"

### 편 3. 말 대신 그림 한 장, 숫자 하나는 크게
- 훅: "'깔끔하게 해줘'는 AI가 알아듣지 못합니다"
- 대본
  - 0~3초 훅
  - 3~15초: 배치는 사람이 **스케치 한 장**(종이 사진·PPT 네모)으로 정한다. 칸마다 번호.
  - 15~35초: 같은 숫자의 나쁜 화면(전부 같은 크기·무지개색·파이)과 좋은 화면(핵심 숫자 1개 크게·색은 의미 있을 때만) 전환.
  - 35~45초: 3초 테스트 + 프롬프트
- 화면: 번호 붙은 와이어프레임 → 완성 화면, 가이드 9쪽의 비교 화면.
- 프롬프트: `첨부한 스케치 배치 그대로 만들어 줘. 핵심 숫자 1개만 2배 크기로.`
- 댓글 질문: "3초 안에 핵심 숫자 찾았나요?" (실제 업무 화면은 올리지 않기)

### 편 4. 'AI 티' 지우고 "별로야" 대신 이렇게
- 훅: "보라 그라데이션, 번진 빛, 이모지 아이콘. 이 화면 AI 티 납니다"
- 대본
  - 0~3초 훅
  - 3~20초: 고치는 **순서** 간격 → 색 → 아이콘 → 문구 → 글씨 → 배치 → 디테일 → 그림 → 움직임. 단계마다 화면이 깔끔해지는 전후 비교.
  - 20~38초: "별로야, 다시 해줘" ❌ → 느낌을 말로 바꾸기 ("복잡해요" → "카드 6개 이하로") + **한 번에 3가지, 나머지는 건드리지 말 것**.
  - 38~45초: 프롬프트. 마음에 든 버전은 폴더 복사로 저장.
- 프롬프트: `아래 3가지만 바꾸고 나머지는 건드리지 마. 바꾼 것/안 바꾼 것을 표로 알려 줘.`
- 출처 표기(설명란): "unslop (Damir Sokolovsky, CC BY 4.0) 소개 내용 참고". 설치 방법은 다루지 않기(사내 보안 확인 필요).
- 댓글 질문: "AI 티 나는 디자인 하면 떠오르는 것 하나만?"

### 편 5. AI가 "완성!"이라 해도 믿지 마세요
- 훅: "89.9점은 A일까요 B일까요? AI는 마음대로 정합니다"
- 대본
  - 0~3초 훅
  - 3~15초: 규칙은 **숫자와 경계값**으로 (90.0은 A, 89.9는 B). 빈칸·월 정렬(10월이 2월보다 앞)·비율 식(분모 0이면 "–")도.
  - 15~36초: **정답값 대조표**. D등급 17 vs 16 → ✗ 원인 후보 "60.0점 경계값". 엑셀에서 숫자 3개 직접 계산.
  - 36~45초: 새 대화에서 한 번 더 검토 + 프롬프트
- 프롬프트: `이 대조표와 규칙표를 보고 틀릴 수 있는 곳 3개를 찾아 줘.` (가상 데이터만)
- 댓글 질문: "우리 업무의 애매한 기준은 뭔가요?"

### 편 6. 오류가 나면, 올리기 전에
- 훅: "화면이 하얗게 비었다면 F12 한 번이면 됩니다"
- 대본
  - 0~3초 훅
  - 3~20초: **F12 → Console의 빨간 글씨를 그대로 복사**해 AI에게. 업체명·금액이 섞였으면 지우고. 흔한 함정 자막(코드가 중간에 끊김 / `index.html.txt` / 10월이 앞).
  - 20~40초: 공유 전, 엑셀·키는 저장소에 올리지 않기("지워도 이력에 남습니다"). `.gitignore` + 커밋 전 점검. 갱신은 교체→빌드→점검→배포→확인, 경고 0건이 아니면 배포하지 않기.
  - 40~45초: 프롬프트 + 한 줄(회사 데이터는 밖에서 보게 하지 않고 담당자와 상의)
- 프롬프트: `엑셀 같은 데이터 파일이 저장소에 올라가지 않게 막아 줘. 일부러 엑셀을 추가해서 막히는지 보여 줘.`
- 댓글 질문: "가장 오래 헤맨 오류는?"

## 3. 업로드와 운영

- 주 2편, 3주 완결 (편 1·2 → 3·4 → 5·6). 재생목록: "AI로 대시보드 만들기".
- 마지막 화면 고정 문구: "전체 가이드(21쪽)는 [사내 위치]에서" (위치를 채울 것). 편 끝에 다음 편 예고 한 줄.
- 고정 댓글 한 줄 요약:
  1. 질문 한 문장부터. 2. AI에는 열 이름과 가상 값만. 3. 배치는 스케치, 핵심 숫자는 하나만 크게. 4. AI 티는 순서대로, 수정은 3가지씩. 5. 규칙은 숫자로, 결과는 대조표로. 6. 오류는 F12 글씨 그대로, 데이터는 올리지 않기.

## 4. 공통 제작 규칙

1. **실제 업체명·점수·사내 화면은 절대 화면에 넣지 않습니다.** 가이드의 가상 샘플(1,248개·82.9점)만 사용.
2. 사내 도구 로그인 화면·주소·계정은 가려서 촬영.
3. 프롬프트는 화면에 큰 글씨 한 줄로 띄우고, 설명란에 전문을 넣어 복사하게 합니다.
4. 외부 영상·글의 화면과 그림은 가져다 쓰지 않습니다. 아이디어를 쓴 경우 출처 표기(혼잡스, 복리부자, Notion 공개 자료, unslop CC BY 4.0).
5. 도구의 기능·요금·버전은 바뀌므로 영상에서 특정 버전·요금을 말하지 않습니다.
6. 클라우드 방식(Supabase·Vercel)은 다루지 않거나 "연습용, 가상 숫자만" 한 줄로만 언급합니다.
7. 음원·효과음은 사용 허가된 것만. 자막은 맞춤법 점검 후 업로드.

## 5. 한 편 체크리스트

- [ ] 훅이 3초 안에 끝났고 해결책을 미리 말하지 않았다
- [ ] 한 편에 남기는 행동이 하나뿐이다 (45초 이내)
- [ ] 화면에 실제 데이터·사내 화면이 없다
- [ ] 프롬프트가 자막으로 보이고 설명란에 전문이 있다
- [ ] 소리 끄고 봐도 이해된다
- [ ] 마지막에 댓글 질문 + 다음 편 예고가 있다
