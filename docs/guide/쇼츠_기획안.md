# 교육용 쇼츠 기획안 — "AI로 대시보드, 처음부터 다시 만들지 않기"

가이드(`index.html`, 21쪽)를 **45초짜리 쇼츠 11편**으로 나눕니다. 한 편에 한 가지만 가르치고, 보고 나서 바로 복사해 쓸 **프롬프트 한 줄**을 남깁니다.

## 1. 기본 설정

| 항목 | 내용 |
|---|---|
| 대상 | 코딩을 모르고, AI로 업무용 대시보드를 처음 만들어 보는 사람 |
| 목표 | 시청 후 "AI에게 이렇게 말하면 되는구나"를 하나 가져가기 |
| 형식 | 세로 9:16, 40~50초(60초 넘기지 않기), 한 편 한 주제 |
| 말투 | 쉬운 말, 전문용어는 첫 등장에 한 줄 풀이 (예: "KPI = 대시보드의 핵심 숫자") |
| 구성 | 훅 3초 → 문제 8초 → 해결·시연 25초 → 한 줄 정리 + 프롬프트 7초 → 댓글 질문 |
| 자막 | 필수. 소리 없이도 이해되게, 큰 글씨 한 줄 12자 안팎 |
| 화면 | 전부 **가상 데이터**. 가이드의 나쁜/좋은 화면 비교, 스케치, 프롬프트 상자를 그대로 쓰기 |
| 톤 | 차분하고 친절하게. 과장·공포 마케팅 없이 "한 번 해 보면 쉽다" |

## 2. 에피소드 11편

각 편: **훅(첫 3초) → 핵심 → 화면 → 복사할 프롬프트 → 댓글 질문**. 가이드 쪽 번호를 같이 적었습니다.

### EP1. "대시보드 만들어줘"라고 하면 망합니다 (가이드 2·3쪽)
- 훅: "AI한테 '대시보드 만들어줘'라고만 하면, 결국 처음부터 다시 하게 됩니다"
- 핵심: 문제는 AI가 아니라 **순서**. 사람이 정하고(질문·기준·규칙) → AI가 만들고 → 사람이 숫자로 확인.
- 화면: 8스텝 가로 흐름도가 한 칸씩 켜지기. 사람(주황)/AI(파랑) 색 구분.
- 남기는 것: 입력 → 과정 → 출력 세 칸 그림. "과정은 AI가, 입력과 출력은 내가."
- 댓글 질문: "AI로 뭘 만들다 처음부터 다시 해본 적 있나요?"

### EP2. 엑셀을 통째로 붙여넣지 마세요 (가이드 5·7쪽)
- 훅: "엑셀 내용 그대로 AI에 붙여넣으면 못 되돌립니다"
- 핵심: AI에게는 **열 이름 + 형식 + 가상 값**만. 업체명·금액·개인정보·키는 주지 않는다.
- 화면: 붙여넣기 ❌ 화면(빨간 X) vs 열 이름만 적은 ✅ 화면. "값은 가상으로 만들어"만 강조.
- 프롬프트: `열 이름과 형식만 알려 줄게. 값은 가상으로 만들어 줘.`
- 이미 붙여넣었다면: "멈추고 담당자에게 알리기" 한 줄.
- 댓글 질문: "회사에서 AI에 올리면 안 되는 것, 우리 팀은 정해져 있나요?"

### EP3. 질문 한 문장이 대시보드의 반입니다 (가이드 6쪽)
- 훅: "차트 10개보다 질문 1개가 먼저입니다"
- 핵심: "무엇을 보여 줄까"가 아니라 "이 화면으로 **무엇을 결정**할까". 첫 버전(MVP)은 질문 1~2개.
- 화면: ❌ "매출 대시보드 만들어줘" / ✅ "팀장이 월요일 회의에서 1분 안에…" 두 문장 비교.
- 프롬프트: `이 질문에 답하는 KPI와 화면만 제안해 줘. 답하지 않는 차트는 넣지 마.`
- 댓글 질문: "내 대시보드가 답해야 할 질문은?"

### EP4. 말로 설명 말고 스케치 한 장 (가이드 8쪽)
- 훅: "'깔끔하게'는 AI가 알아듣지 못합니다"
- 핵심: 배치는 사람이 **그림 한 장**(종이 사진·PPT 네모 상자)으로 정한다. 칸마다 번호.
- 화면: 번호 붙은 와이어프레임(메뉴·핵심 숫자·추이·표)이 완성 화면으로 바뀌는 전환.
- 프롬프트: `첨부한 스케치 배치 그대로 목업을 만들어 줘. 스케치에 없는 칸은 넣지 마.`
- 댓글 질문: "스케치 그려 보고 올려 주실 분?" (※ 실제 업무 화면은 올리지 않기)

### EP5. 보기 좋은 대시보드는 '눈 갈 곳이 정해진' 화면 (가이드 9쪽)
- 훅: "숫자는 같은데, 왜 오른쪽만 읽힐까요?"
- 핵심: ① 핵심 숫자 1개를 크게 ② 색은 의미 있을 때만 ③ 차트는 단순하게 ④ 기준선과 한 줄 해석 ⑤ 숫자는 소수 1자리.
- 화면: 가이드의 **나쁜 화면(전부 같은 크기·무지개색·파이)** → **좋은 화면** 전환. 3초 테스트 자막.
- 프롬프트: `핵심 숫자 1개만 2배 크기로, 색은 회색 기본에 파랑·빨강만 써 줘.`
- 댓글 질문: "3초 안에 핵심 숫자 찾았나요?"

### EP6. 'AI 티' 지우는 순서 (가이드 10쪽)
- 훅: "보라 그라데이션, 번진 빛, 이모지 아이콘. 이 화면 AI가 만든 티 납니다"
- 핵심: 고치는 순서 **간격 → 색 → 아이콘 → 문구 → 글씨 → 배치 → 디테일 → 그림 → 움직임**. 한 단계씩.
- 화면: AI 티 나는 화면에서 한 단계 지날 때마다 깔끔해지는 전후 비교 (가상 화면).
- 프롬프트: `아래 기준으로 화면을 점검하고, 어긋난 곳 5개만 알려 줘. 아직 고치지는 마.`
- 출처 표기: 설명란에 "unslop (Damir Sokolovsky, CC BY 4.0) 소개 내용 참고". 설치 방법은 다루지 않기(사내 보안 확인 필요).
- 댓글 질문: "AI 티 나는 디자인 하면 떠오르는 것 하나만?"

### EP7. "별로야" 대신 이렇게 말하세요 (가이드 11쪽)
- 훅: "'별로야, 다시 해줘'는 마음에 들던 부분까지 지워 버립니다"
- 핵심: 느낌 → 말 바꾸기. "복잡해요" → "카드 6개 이하로, 질문과 무관한 차트는 빼 줘". **한 번에 3가지**, 나머지는 건드리지 말 것.
- 화면: 느낌→말 표 4줄이 하나씩 변환. 수정 틀 프롬프트.
- 프롬프트: `아래 3가지만 바꾸고 나머지는 건드리지 마. 바꾼 것/안 바꾼 것을 표로 알려 줘.`
- 덤: 마음에 든 버전은 폴더 복사 `v2`로 저장.
- 댓글 질문: "AI가 멋대로 다른 데까지 바꾼 경험 있나요?"

### EP8. 규칙은 숫자로 못 박기 (가이드 12쪽)
- 훅: "89.9점은 A일까요 B일까요? AI는 마음대로 정합니다"
- 핵심: 구간·**경계값**(90.0은 A, 89.9는 B)·빈칸 처리·월 정렬(10월이 2월보다 앞에 나오는 문제)·비율 식(분모 0이면 "–")까지 숫자로.
- 화면: 등급 표에서 90.0 / 89.9에 형광 표시, 정렬 오류 화면 → 해결.
- 프롬프트: `숫자가 달라질 수 있는 모호한 규칙을 질문으로 뽑아 줘. 내가 답하면 규칙표로 정리해 줘.`
- 댓글 질문: "우리 업무의 애매한 기준은 뭔가요?"

### EP9. AI가 "완성!"이라 해도 믿지 마세요 (가이드 15쪽)
- 훅: "화면이 그럴듯해도 숫자는 틀릴 수 있습니다"
- 핵심: **정답값 대조표**(기대값/실제값/일치) + 엑셀에서 숫자 3개 직접 계산 + **새 대화에서 한 번 더 검토**.
- 화면: 대조표에서 한 줄만 ✗(D등급 17 vs 16) → 원인 후보 "60.0점 경계값".
- 프롬프트: `이 대조표와 규칙표를 보고 틀릴 수 있는 곳 3개를 찾아 줘.` (가상 데이터만)
- 댓글 질문: "숫자 틀린 대시보드 보고서에 올라간 적 있나요?"

### EP10. 오류가 나면 이것부터 (가이드 17쪽)
- 훅: "화면이 하얗게 비었다면 F12 한 번이면 됩니다"
- 핵심: **F12 → Console의 빨간 글씨를 그대로 복사**해 AI에게. 이해하려 애쓰지 않기. 업체명·금액이 섞였으면 지우고 붙이기.
- 화면: F12 누르는 손 모양 연출(가상 페이지), 만능 질문 형식 프롬프트.
- 함정 3개 자막: 코드가 중간에 끊김(`</html>`로 안 끝남) / 파일명이 `index.html.txt` / 10월이 2월보다 앞.
- 댓글 질문: "가장 오래 헤맨 오류는?"

### EP11. 엑셀과 키는 저장소에 올리지 마세요 (가이드 16쪽)
- 훅: "지워도 이력에 남습니다. 사내 저장소도 마찬가지입니다"
- 핵심: 화면 파일만 공유, 데이터는 `.gitignore` + 커밋 전 점검. 갱신은 교체→빌드→점검→배포→확인(경고 0건이 아니면 배포하지 않기). 되돌릴 수 없는 일은 사람이 확인.
- 화면: 엑셀을 추가하니 커밋이 막히는 장면(가상 파일).
- 덤(선택 1컷): "밖에서도 보고 싶다면 주소를 그냥 열지 말고 로그인 제한부터. 회사 데이터는 담당자와 상의"
- 댓글 질문: "우리 팀 데이터는 어디에 보관하나요?"

## 3. 추천 업로드 순서와 묶음

| 순서 | 편 | 이유 |
|---|---|---|
| 1 | EP1 → EP2 | 문제 제기 + 안전 (가장 먼저 알아야 함) |
| 2 | EP3 → EP4 → EP5 → EP6 | 만들기 전 준비 + 보기 좋게 (조회가 가장 잘 나올 구간) |
| 3 | EP7 → EP8 → EP9 | 고치기·규칙·검증 |
| 4 | EP10 → EP11 | 막혔을 때 + 공유 |

- 주 2~3편, 4주 완결. 재생목록 이름: "AI로 대시보드 만들기 (처음부터 다시 하지 않기)".
- 마지막 화면 고정 문구: "전체 가이드(21쪽)는 [사내 위치]에서". 링크는 사내 위치로 채울 것.
- 한 편 끝에 **다음 편 예고 한 줄**(예: "다음: 스케치 한 장").

## 4. 공통 제작 규칙

1. **실제 업체명·점수·사내 화면은 절대 화면에 넣지 않습니다.** 가이드의 가상 샘플(1,248개·82.9점)만 사용.
2. 사내 도구 로그인 화면·주소·계정은 가려서 촬영.
3. 프롬프트는 화면에 **큰 글씨 한 줄**로 띄우고, 설명란에 전문을 넣어 복사하게 합니다.
4. 외부 영상·글의 화면과 그림은 가져다 쓰지 않습니다. 아이디어를 쓴 경우 설명란에 출처 표기(혼잡스, 복리부자, Notion 공개 자료, unslop CC BY 4.0).
5. 도구의 기능·요금·버전은 바뀌므로 영상에 특정 버전·요금을 말하지 않습니다.
6. 음원·효과음은 사용 허가된 것만. 자막은 맞춤법 점검 후 업로드.
7. 클라우드 방식(Supabase·Vercel)은 "연습용, 가상 숫자만"으로 한 줄만 언급하고 따라 하기를 권하지 않습니다.

## 5. 한 편 제작 체크리스트

- [ ] 훅이 3초 안에 끝나고, 결론(해결책)을 미리 말하지 않았다
- [ ] 한 편에 가르치는 것이 하나뿐이다 (45초 이내)
- [ ] 화면에 실제 데이터·사내 화면이 없다
- [ ] 프롬프트가 자막으로 보이고 설명란에 전문이 있다
- [ ] 소리 끄고 봐도 이해된다
- [ ] 마지막에 댓글 질문 + 다음 편 예고가 있다

## 7. 편별 한 줄 요약 (고정 댓글용)

1. 사람이 정하고, AI가 만들고, 숫자로 확인합니다.
2. AI에는 열 이름과 가상 값만 줍니다.
3. 질문 한 문장부터 정합니다.
4. 배치는 스케치 한 장으로 전합니다.
5. 핵심 숫자 1개를 크게, 색은 의미 있을 때만.
6. AI 티는 간격부터 차례로 지웁니다.
7. "별로야" 대신 무엇을 어떻게 바꿀지 말합니다.
8. 경계값까지 숫자로 적습니다.
9. 정답값과 직접 계산으로 검증합니다.
10. 오류는 F12 글씨 그대로 AI에게.
11. 데이터는 올리지 않고 화면만 공유합니다.
