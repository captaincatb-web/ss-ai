원리와 작업 흐름
왜 서버 없이 되는지,
AI와 어떻게 나눠 만드는지
약 25분
    2.1

    세 가지 설계 결정이 전부입니다

    1

    서버가 없다

    결과물은 HTML·CSS·JS 파일뿐입니다. 더블클릭하면 열리고, 폴더를 복사하면 배포가 끝납니다.

    → 서버·DB·권한 신청이 필요 없다

    2

    계산은 빌드 때

    엑셀 읽기·정리·가중 평균·등급·전년 연결은 빌드에서 끝냅니다. 브라우저는 필터한 목록을 세고 그립니다.

    → 화면이 느릴 이유가 없다

    3

    데이터는 파일이다

    엑셀을 읽어 data.js 한 파일로 만듭니다. 갱신은 엑셀 교체 → 빌드 1회입니다.

    → 고장 날 곳이 적고 어디든 옮길 수 있다

    무거운 일은 빌드에서 끝내고,
    브라우저는 그림만 그린다.
    2.2

    전체 구조 — 엑셀에서 화면까지 한 줄기

    엑셀 원본병합 셀·2행 헤더까지
    있는 그대로
    →
    빌드 build.py읽기 → 정리 →
    계산 → 내보내기
    →
    dist/ 폴더data.js · 점검 리포트
    index.html
    →
    브라우저data.js를 읽어
    그림만 그림
    사람

    하는 일

    엑셀을 갱신하고 빌드를 1번 실행한 뒤, 점검 리포트의 경고가 0건인지 봅니다.

    빌드 · 무거운 일

    엑셀을 믿지 않는다

    정리·계산·점검을 합니다. 데이터 오류는 여기서 잡습니다.

    브라우저 · 가벼운 일

    그림만 그린다

    필터한 목록의 평균·개수를 세고 차트·표를 그립니다. 서버 통신이 없습니다.

    2.3

    이런 경우에 맞고, 이런 경우에는 안 맞습니다

    맞는 경우

    • 읽고 보는 것이 중심
    • 갱신이 일·주·월 단위
    • 데이터가 수천~수만 행
    • 같은 화면을 여러 명이 봄
    • 서버를 새로 두기 어려움

    다른 구조가 필요한 경우

    • 화면에서 데이터를 입력·수정
    • 실시간으로 계속 바뀜
    • 사람마다 볼 수 있는 데이터가 다름(권한)
    • 수십만 행 이상
    • 다른 시스템과 양방향 연동
    판단 질문 하나
    사람이 이 화면에서 데이터를 바꾸나요? 그렇다면 정적 대시보드가 아닙니다.
    2.4

    5단계 로드맵 — 이 순서를 지킵니다

    1 설계3장 · 질문 → 화면
    2 데이터 계약4장 · 열·키·단위
    3 빌드5장 · 엑셀 → data.js
    4 화면6장 · 차트·표
    5 설정·배포7장 · 기준 분리·공유

    2.5

    AI와 함께 만드는 6단계

    이 대시보드도 이 순서로 만들었습니다 — 목업 1개 → 지시서 2개 → 단계별 구현

    1
    질문·화면 정하기 사람

    누가 무엇을 결정하려고 보는가

    2
    가상 데이터로 목업 만들기 AI 사람

    눈으로 보고 계속 고친다 — 구현 전에 많이 고칠수록 싸다

    3
    구현 지시서 쓰기 AI 초안 사람 검수

    본문 + 부록(코드·정답값)

    4
    사내 AI 도구로 단계별 구현 AI

    M0 → M9, 단계마다 보고

    5
    정답값·체크리스트로 검증 사람

    숫자가 정답값과 같은지, 경고가 0건인지

    6
    배포·갱신 사람

    엑셀 교체 → 빌드 → 점검 → 배포

    사람이 정할 것

    • 질문과 KPI
    • 기준 (등급 구간·목표)
    • 데이터 규칙·보안
    • 최종 검수

    AI에게 맡길 것

    • 구조 설계·코드
    • 테스트·문서
    • 반복 수정
    2.6

    구현 지시서는 이렇게 구성합니다

    AI가 헤매지 않으려면 규칙·숫자·정답이 글로 있어야 합니다

    본문 — 무엇을, 어떻게

    요약 · 절대 규칙 · 진행 단계(M0~M9) · 폴더 · 데이터 읽기 규칙 · 계산 규칙 · 디자인 · 화면 명세 · 검증 체크리스트 · 가정 목록 · 보고 양식

    부록 — 정밀 자료

    CSS · HTML 뼈대 · 설정·열 매핑 · 참조 코드 · 샘플 생성기 · 정답값 · 화면 코드

    좋은 지시서의 다섯 가지 습관

    1
    규칙은 숫자로 쓴다

    "90점 이상 A" + 경계값 테스트 (90.0 → A, 89.9 → B)

    2
    정답값을 같이 준다

    가상 샘플의 정답 숫자 — 만든 결과와 대조하는 기준

    3
    모호한 것은 가정으로 적는다

    질문으로 멈추지 말고 가정 목록에 기록 → 설정으로 뺀다

    4
    하지 말 것을 쓴다

    오프라인·데이터 보호·LLM 호출 코드 금지 같은 절대 규칙

    5
    단계마다 완료 기준을 쓴다

    "이것이 되면 다음 단계" (DoD)

    2.7

    AI 코딩 도구에 처음 보내는 말

    첫 요청문 (줄여 쓴 예)

@docs/지시서_본문.md 를 끝까지 읽고 그대로 따라줘.
(요약 금지 · 문구·수치·색 바꾸지 마)
부록은 필요한 단계에서만 읽어줘.

진행
- M0(환경 점검) → M9, 단계가 끝나면 10줄로 보고
- 막히지 않으면 멈추지 말고 다음 단계로
- 단계마다 PROGRESS.md 에 "끝낸 일 · 다음 할 일" 기록

데이터
- 엑셀 위치: <내 PC 폴더>  (경로는 --data-dir 인자로)
- 엑셀 내용은 대화·로그·커밋에 출력 금지, 외부 통신 금지

먼저 물어볼 것: git push, 삭제·덮어쓰기
그럼 M0부터 시작해줘.
