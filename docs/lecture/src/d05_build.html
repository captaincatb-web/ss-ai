빌드
3단계 — 무거운 일은 빌드에서 끝내고,
화면에는 정리된 데이터만 넘깁니다
약 30분
    5.1

    빌드는 네 단계로 나눕니다

    원본을 믿지 않는 단계
    화면이 쓰기 좋은 모양을 만드는 단계
    ① Read

    읽기

    엑셀을 있는 그대로 행 목록으로. 헤더 행 찾기 · 병합 풀기

    ② Normalize

    정리

    이름·숫자·빈칸을 정돈. 동의어 · 키 · 범위 점검

    ③ Compute

    계산

    등급 · 순위 · 전년 연결 · 추이 · 가중 평균

    ④ Emit

    내보내기

    data.js + 점검 리포트 + dist/

    섞으면 디버깅이 불가능합니다
    읽으면서 계산하고, 계산하면서 고치면 어디서 틀렸는지 알 수 없습니다. 단계 사이의 중간 결과를 눈으로 볼 수 있어야 합니다.
    5.2

    모듈마다 책임은 하나, 하지 않는 일도 정한다

    모듈(함수)하는 일하지 않는 일
    read_excel파일 열기 · 헤더 행 찾기 · 병합 풀기값을 고치지 않는다
    find_col · num동의어로 열 찾기 · 숫자·빈칸 정리계산하지 않는다
    compute등급 · 키 점검 · 전년 연결 · 추이엑셀을 직접 읽지 않는다
    emitdata.js · 점검 리포트 · dist/ 복사숫자를 바꾸지 않는다
    warn경고를 모아서 보고멈추지 않는다 (치명 오류만 중단)
    파일이 길어지면 이 경계로 쪼갭니다
    실습 키트의 build.py는 한 파일(약 270줄)이지만 함수가 이 경계로 나뉘어 있습니다. 새 규칙은 어느 함수에 들어갈지 먼저 정합니다.
    5.3

    코드 골격 — 이것만 읽으면 흐름이 보입니다

    실습 키트 build.py에서 뽑은 부분입니다

    main() — 네 단계가 그대로 보인다

    def main():
    S = read_settings(HERE / 'settings.js')           # 설정: 기준·열 이름
    for f in folders:                                  # ① 읽기 — 연도 폴더마다

    size = emit(model, out)                            # ④ data.js · 점검 리포트 · dist/
    say('점검', f'경고 {len(WARNINGS)}건')              # 0건이 아니면 배포하지 않는다

    숫자 정리 — 엑셀은 글자를 섞어 놓는다

    def num(v):    # '90%' ' 87점' → 숫자
    if v in (None, ''): return None
    if isinstance(v, (int, float)): return float(v)
    t = re.sub(r'[^\d.\-]', '', str(v))
    try: return float(t)

    5.4

    계산 규칙은 한 곳에서, 숫자로 고정합니다

    규칙정의경계·예
    등급90 이상 A · 80 이상 B · 60 이상 C · 그 외 D90.0→A · 89.9→B · 80.0→B · 79.9→C · 60.0→C · 59.9→D
    증감 표기▲ 1.3점 / ▼ 2.1점 / – 0.0점반올림해서 0.0이면 회색 "– 0.0점"
    순위높은 순, 동점은 같은 순위, 빈 값 제외90 · 85 · 85 · 80 → 1 · 2 · 2 · 4
    평균빈 값은 제외하고 평균 (0으로 세지 않음)[80, 빈칸, 90] → 85
    가중 평균가중치(거래비중 등)가 있으면 Σ(점수×비중) ÷ Σ(비중)비중 합이 100이 아니면 경고
    추이(코호트)기준연도 평가 협력사 집단을 과거까지 따라간다연도마다 대상이 달라도 같은 집단 비교
    엑셀에 등급이 이미 있다면?
    어느 쪽을 믿을지 정해 두고(키트: 계산값 · 실제 프로젝트: 엑셀 값 우선) 서로 다르면 경고로 남깁니다. 규칙은 설정과 함수 한 곳에만 두고, 화면 코드에 90 같은 숫자를 박지 않습니다.
    5.5

    산출물은 dist/ 폴더 하나

    이 폴더만 옮기면 어디서나 열립니다

    빌드 후 dist/ (실습 키트)

    dist/
├─ index.html       화면 (data.js?v=빌드시각 으로 캐시 방지)
├─ settings.js      기준·열 이름 (설정 복사본)
├─ data.js          window.__DATA__ = {…}  ← 화면이 읽는 데이터
└─ data_check.txt   점검 리포트

    실제 프로젝트에서는 이렇게 늘어납니다

    styles.css · app.js      화면 코드를 파일로 분리
data_check.html          보기 좋은 점검 리포트
chat-adapter.js          AI 대화를 연결할 때만

    왜 JS 파일인가

    file://(더블클릭)에서는 fetch로 JSON을 읽을 수 없어서 data.js를 <script>로 읽습니다.

    같은 파일, 어디서나

    더블클릭으로도, 서버에 올려도 코드 수정 없이 똑같이 동작합니다.

    못 읽으면 오류 화면

    data.js가 없으면 샘플로 대신 보여 주지 않고 원인을 알려 줍니다.

    5.6

    빌드 성공 ≠ 데이터 정상 — 점검 리포트

    일부러 문제 5가지를 섞은 엑셀로 빌드한 결과

    [읽기] 2026/영역점수.xlsx → 영역점수, 헤더 2행, 199행
[읽기] 2026/평가결과.xlsx → 평가결과, 헤더 3행, 201행
[경고] 협력사 코드가 없는 행 1개 → 제외했습니다.
[경고] 협력사 코드가 중복된 행 1개 → 처음 나온 행만 사용했습니다.
[경고] 점수가 비었거나 0~100 밖인 행 1개 → 제외했습니다.
[경고] 엑셀의 등급과 점수로 계산한 등급이 다른 협력사 1개
       (예: S0020(85.0점: 엑셀 A ≠ 계산 B)) → 계산한 등급을 씁니다.
[경고] 키 불일치: 평가결과에만 있음 1개 ['S0030'],
       영역점수에만 있음 2개 ['S0004', 'S0011']
[정리] 기준연도 2026 · 협력사 198개 · 추이 자료 2/5개년 [2025, 2026]
[정답값] 평균 80.8점(전년 80.5) · A 30 / B 77 / C 90 / D 1
[점검] 경고 5건

    읽는 법

    • 경고 0건 = 배포해도 좋다
    • 1건 이상 = 원인 확인 전 배포 금지
    • 행 수는 엑셀과 대조
    • 정답값은 기대값과 대조
    경고 하나가 다른 경고를 낳기도 합니다
    점수 범위 밖으로 제외된 행이 "영역점수에만 있음"으로도 나옵니다.
    5.7

    같은 입력은 같은 결과 — 그리고 정답값

    멱등성

    빌드를 몇 번 돌려도 같은 결과. 바뀌는 것은 갱신 시각뿐입니다.

    결정성

    가상 샘플은 시드를 고정해서 만듭니다. 누가 만들어도 같은 숫자가 나옵니다.

    정답값(골든 값)

    가상 샘플의 정답 숫자를 적어 두고, 만든 결과와 대조합니다.

    가상 샘플시드 고정
    →
    엑셀로 저장실제와 같은 헤더 구조
    →
    build읽기 → … → 내보내기
    →
    화면 숫자평균 · 등급 개수
    =
    정답값?다르면 규칙 오류
    예: 이 사례의 정답값 (가상 샘플)
    평균 82.9점 (전년 81.6) · 등급 A 211 / B 648 / C 372 / D 17 — AI가 만든 화면이 이 숫자와 다르면 구현이 어긋난 것입니다.
