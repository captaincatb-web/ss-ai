    화면 갱신카드·차트·표

    실습 키트 index.html에서 (줄여 옮김)

    const state = { group: '', q: '', sort: 'desc', limit: 20 };
const filtered = () => D.suppliers.filter(x =>
  (!state.group || x.group === state.group) &&
  (!state.q || (x.name + x.code).includes(state.q)));

function render() {
  const L = filtered();         // 모든 카드는 같은 목록 L 에서
  $('#app').innerHTML = kpis(L) + gradeCard(L) + areaCard(L)
                      + trendCard(L) + tableCard(L);
  // 이벤트: state 를 바꾸고 render() 를 다시 부른다
}

    왜 이렇게?

    • 숫자가 서로 어긋나지 않는다 (같은 L)
    • 고칠 곳이 한 곳
    • 해시(#report)로 화면을 기억 → 새로고침·링크 공유

    6.4

    드릴다운은 이전 선택을 물려받습니다

    "왜 이 숫자인지"가 끊기지 않게 — 선택은 다음 화면까지 이어집니다

    결과 요약핵심 숫자 · 명단 링크
    →
    항목별 결과영역 → 평가항목
    →
    협력사별 결과목록 → 개별 상세

    필터는 전 화면

    한 줄 필터를 바꾸면 모든 화면이 같은 목록으로 다시 계산됩니다.

    링크는 목적지까지

    "부진사 명단 →"을 누르면 협력사별 결과로 가서 그 칩이 이미 선택되어 있습니다.

    행 클릭 = 상세

    목록의 행을 누르면 그 협력사의 상세로. 해시에 기억돼 링크로 공유됩니다.

    설계 규칙
    모든 화면에는 "다음에 어디로 가는가"가 있어야 합니다. 막다른 숫자는 질문을 끝내지 못합니다.
    6.5

    현장에서 꼭 필요한 기능 6가지

    상세 보기

    기본은 핵심만. 버튼을 켜면 세부 카드·표가 펼쳐집니다.

    표 보기

    차트 ↔ 같은 숫자의 표. 정확한 값 확인과 접근성.

    출처 i 버튼

    카드가 쓰는 엑셀 열 이름이 보입니다. 숫자를 의심할 때 추적.

    CSV 내려받기

    UTF-8 BOM을 붙여야 엑셀에서 한글이 깨지지 않습니다.

    인쇄 · PDF

    @media print로 메뉴·필터를 숨기고 A4 보고서로.

    AI 대화 패널

    화살표 손잡이로 여는 오른쪽 패널. 디자인과 열고 닫기만 — API는 연결 자리만 둡니다.

    AI 패널에 LLM 호출 코드를 넣지 않는 이유
    주소·키가 코드에 들어가면 저장소로 새어 나갑니다. window.SUPPLIER_CHAT.ask 한 곳만 비워 두고, 연결은 별도로 합니다.
    6.6

    접근성과 성능 — 기본 점검 항목

    접근성

    • 키보드(Tab · Enter)로 모든 기능 사용
    • 툴팁이 마우스와 키보드 포커스 모두에서
    • 색만으로 의미를 전달하지 않음 (▲▼ · 글자 병행)
    • 차트에는 표 보기
    • 다크 모드에서도 읽힘

    성능

    • 필터 변경 후 1초 이내 (협력사 5,000개 이하)
    • 표는 한 번에 10행씩
    • 순위·평균은 렌더 한 번에 한 번만 계산
    • 검색 입력은 0.18초 지연 후 반영
    • 창 크기가 바뀌면 차트를 다시 그림
    데이터가 더 커지면?
    5,000행을 넘으면 빌드에서 요약본을 따로 만들어 화면은 요약만 읽게 합니다. 브라우저에서 줄이려 하지 않습니다.
