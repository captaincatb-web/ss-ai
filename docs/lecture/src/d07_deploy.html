    7.1

    바뀔 값은 모두 설정 파일로

    기준이 바뀌면 코드가 아니라 설정을 고치고, 빌드를 다시 합니다

    settings.js (실습 키트에서)

    window.SUPPLIER_SETTINGS = {
  "title": "협력사 종합평가 (실습)",
  // 등급 구간: 점수 이상이면 해당 등급, 그 외는 D
  "gradeCut": { "A": 90, "B": 80, "C": 60 },
  "target": 85,
  "lowLine": 70,
  "areas": ["품질", "납기", "원가", "대응", "기술"],
  "columns": {
    "score": ["종합 점수", "종합점수", "총점"]
  }
}

    설정에 들어갈 것

    등급 구간 · 라벨 · 영역 이름 · 목표·기준선 · 열 동의어 · 임시 기준

    형식 규칙 (키트)

    키·문자열은 큰따옴표, 마지막 쉼표 금지, 주석은 줄 맨 앞 //만

    아직 확정되지 않은 기준은 "임시"로 표시합니다
    이 사례의 부진사·우수사 후보 기준도 처음엔 임시였습니다. 임시 값 + 화면의 "임시 기준" 배지로 시작하고, 확정되면 설정만 바꿉니다.
    7.2

    정적 배포 세 가지 방법

    기본

    ① 각자 PC에서 열기

    저장소를 받아(clone) 본인 엑셀을 넣고 빌드 → 열기.

    • 데이터가 PC 밖으로 나가지 않음
    • 각자 빌드가 필요
    공유

    ② 사내 웹 서버·공유 폴더

    담당자가 빌드한 dist/를 복사. 접근 제한은 서버에서.

    • 링크 하나로 공유
    • 갱신 = 파일 교체
    정책 확인 후

    ③ 사내 GitHub Pages

    발행 전용 브랜치에 dist/를 올려 페이지로.

    • 데이터를 저장소에 올려도 되는지
    • 보기 권한을 제한할 수 있는지
    고르는 기준 질문 하나
    데이터(data.js)가 저장소에 올라가도 되는가? 확실하지 않으면 ①②를 씁니다. ③은 보안 정책을 확인한 뒤에만, 발행 전용 브랜치에 이력 없이 덮어쓰는 방식으로 합니다.
    7.3

    보안 규칙 — 코드는 올리고, 데이터는 올리지 않는다

    하지 말 것

    • 원본 엑셀·CSV·data/를 저장소에 커밋
    • DRM 파일을 평문으로 변환해 배포
    • 토큰·비밀번호를 .js/.env에 하드코딩
    • 사내 데이터를 외부 CDN·외부 LLM에 전송

    할 것

    • .gitignore로 데이터 폴더·엑셀 제외
    • 커밋 전 데이터 포함 검사(훅)
    • 배포 대상은 빌드 산출물(dist/)만
    • 공개 데모는 가상 샘플로 분리
    • 서버에서는 사내망 + 접근 권한 뒤에

    .gitignore

    data/
dist/
build/
*.xlsx
*.xls
.env
    사내 GitHub도 저장소입니다
    접근 권한이 있으면 이력까지 보이고, 올린 파일은 지워도 되살릴 수 있습니다. 저장소 접근 권한과 데이터 접근 권한은 다릅니다.
    7.4

    갱신은 다섯 단계 — 경고 0건이 아니면 배포하지 않는다

    ① 교체엑셀 새 파일
    ② 빌드python build.py
    ③ 점검경고 0건?
    ④ 배포dist/ 복사
    ⑤ 확인숫자 3개 대조

    ③ 점검에서 멈추는 규칙

    data_check.txt의 경고가 1건이라도 있으면 원인을 확인하기 전에는 배포하지 않습니다. 엑셀을 고칠지, 규칙을 고칠지 먼저 정합니다.

    ⑤ 확인은 눈으로

    첫 화면의 숫자 3개(평균 · 협력사 수 · A 비율)를 엑셀에서 직접 계산한 값과 맞춰 봅니다.

    갱신 주기를 정해 두세요
    예: 평가가 확정된 날 · 매월 첫 영업일. 담당자와 대체자 이름을 README에 적어 둡니다.
    7.5

    서버로 옮길 때 확인할 것

    지금은 로컬, 나중에 서버 — 처음부터 이 규칙으로 만들면 코드를 고치지 않습니다

    • 상대 경로만 — 하위 주소(/dash/)에서도 동작
    • 일반 <script>만 — ES 모듈·fetch는 file://에서 막힘
    • UTF-8 — 파일 저장도, 서버 응답도
    • 캐시 — data.js?v=빌드시각, 서버는 no-cache
    • 못 읽으면 오류 화면 — 샘플로 대신 보여 주지 않음
    • 접근 제한 — 서버에서 설정(이 프로젝트는 로그인을 만들지 않음)
    • 경로를 코드에 박지 않기 — 엑셀 위치는 --data-dir 인자
    • 한글·공백 경로에서도 빌드가 되는지

    올리기 전에 서버처럼 먼저 열어 보기

    cd dist
python -m http.server 8000
# 브라우저에서 http://localhost:8000/ 로 확인
    같은 파일이 두 방식에서 똑같이 열려야 합니다
    더블클릭(file://)과 서버(http://) 모두에서 첫 화면·필터·오류 화면을 확인하세요.
