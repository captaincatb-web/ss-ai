# opencode에 처음 보낼 요청문

## 1. 파일 놓기

opencode가 열 **프로젝트 폴더** 안에 `docs/`를 만들고 아래 3개를 복사합니다. 엑셀은 문서 폴더가 아니라 `data/<기준연도>/`(또는 원하는 폴더)에 둡니다.

```
supplier-dashboard/
├─ docs/
│   ├─ opencode_프롬프트_본문.md
│   ├─ opencode_프롬프트_부록.md
│   └─ 종합평가_대시보드_목업.html      (기준 화면 — 수정하지 않고 비교만)
└─ data/<기준연도>/  (엑셀 4종 — 커밋 금지. 지금은 1개년만)
```

- 첨부(`@`) 기능이 있으면 **본문만** 첨부하세요. 부록(약 14만 자)과 목업까지 첨부하면 처음부터 컨텍스트가 가득 차므로 경로만 적어 두고 단계마다 읽게 합니다.

## 2. 첫 요청문 (복사해서 붙여넣기)

`<엑셀 폴더 경로>` 한 곳만 채우세요.

```text
협력사 종합평가 대시보드를 만들 거야. 구현 지시서와 자료는 프로젝트 폴더의 docs/ 에 넣어 뒀어.

@docs/opencode_프롬프트_본문.md 를 처음부터 끝까지 읽고 그대로 따라줘. (요약하지 말고, 문구·수치·id·색은 바꾸지 마. 한 번에 안 읽히면 나눠서 끝까지.) 다 읽었으면 어느 절(§)까지 읽었는지 한 줄만 알려주고 바로 시작해.

참고 자료 (필요한 단계에서만 읽어줘 — 통째로 읽지 마)
- docs/opencode_프롬프트_부록.md : M1 → C·E·F / M2 → A·B / M3 → D / M4~M6 → G·F / M7 → C / M9 → F
- docs/종합평가_대시보드_목업.html : 기준 화면. 수정하지 말고 브라우저로 열어 비교만 해. 화면·동작이 본문과 다르면 목업이 우선, 데이터 읽기·계산은 본문이 우선.

진행
- M0(환경 점검, 코드 작성 금지) → M9 순서대로. 단계가 끝나면 10줄 이내로 보고하고, 막히지 않으면 멈추지 말고 다음 단계로. M10은 하지 마(필요하면 내가 따로 요청).
- 모호하면 질문으로 멈추지 말고 가정을 기록(본문 §14 형식)하고 진행해.
- 컨텍스트가 길어질 수 있으니 단계가 끝날 때마다 PROGRESS.md에 "끝낸 단계 · 검증 결과 · 다음 할 일"을 갱신해줘.

데이터
- 엑셀 4종은 지금 내 PC에 있어: <엑셀 폴더 경로>  (지금은 기준연도 1개년만 있고, 과거 연도는 나중에 폴더로 추가할 거야 — 본문 §6.9)
- 나중에 사내 GitHub/서버로 올릴 거라 본문 §5.1·§5.2를 지켜줘. 경로는 코드에 박지 말고 --data-dir 인자로 받아.
- 엑셀 내용(업체명·점수 등)을 대화·로그·커밋에 출력하지 말고 건수와 집계만 보고해. data/ dist/ 는 커밋 금지.
- 외부 통신(CDN·웹폰트·외부 API) 금지.

나에게 먼저 물어볼 것: git push, 되돌리기 어려운 삭제·덮어쓰기, 지시서와 모순되는 요구를 발견했을 때.

그럼 M0부터 시작해줘.
```

## 3. 파일을 폴더에 넣을 수 없을 때 (붙여넣기)

1. 본문 전체 → 부록 A·B → 부록 C~F → 부록 G 순서로 **4번에 나눠** 붙여넣습니다. 각 입력 끝에 「다음 파트를 이어서 입력합니다. 전부 받기 전에는 구현을 시작하지 마세요.」를 붙입니다.
2. 마지막에 위 요청문에서 `@…` 줄과 「참고 자료」 블록만 빼고 보냅니다.

## 4. 대화를 새로 시작해야 할 때

```text
PROGRESS.md 와 docs/opencode_프롬프트_본문.md(§2 절대 규칙, §4 진행 방식)를 읽고, 끝낸 단계 다음부터 이어서 해줘.
```
