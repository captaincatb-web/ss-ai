# 협력사 종합평가 대시보드 — opencode 구현 프롬프트 (본문)

> **사람용 안내** (opencode에 입력할 때는 이 블록을 빼도 됩니다)
> 1. 이 파일이 **본문**입니다. 같은 폴더에 **부록**(`opencode_프롬프트_부록.md`)과, 있다면 기준 화면 `종합평가_대시보드_목업.html`을 함께 두고 이렇게 입력하세요.
>    **"opencode_프롬프트_본문.md를 처음부터 끝까지 읽고, 부록을 참조해서 M0 단계부터 순서대로 구현해줘."**
> 2. 파일을 올릴 수 없고 붙여 넣어야 한다면 ① 본문 → ② 부록 A·B → ③ 부록 C~F → ④ 부록 G(선택) 순서로 나눠 입력하세요. 각 입력 끝에 "다음 파트를 이어서 입력합니다. 전부 받기 전에는 구현을 시작하지 마세요."를 붙이고, 마지막에 "M0부터 시작해줘"라고 하면 됩니다.
> 3. 본문만으로도 구현할 수 있게 썼습니다. 부록은 색·간격·차트 모양과 샘플 숫자까지 목업과 똑같이 만들기 위한 정밀 자료입니다.
> 4. 사내 엑셀 4종은 이 문서에 들어 있지 않으며, opencode가 실행되는 사내 환경에서만 읽습니다.

## 0. 요약

**만들 것**: 사내 엑셀 4종(연도별 — **기준연도 1개년부터 시작해 최대 5개년**)을 읽어 **협력사 종합평가 결과**를 보여 주는 **오프라인 웹 대시보드**. **지금은 로컬**(엑셀도 내 PC 폴더, `index.html` 더블클릭)에서 쓰고, **나중에 서버에 올려도** 코드를 고치지 않고 똑같이 동작해야 합니다(§5.1).

**화면 3개** (왼쪽 메뉴)
| 메뉴 | 해시 | 하는 일 |
|---|---|---|
| 결과 요약 (첫 화면) | `#report` | 평균 점수 · 등급별 개수/비율 · 5개년 추이 · 항목별 전년/올해 증감 · 변화가 큰 업종/협력사 · 부진사 · 우수사 후보 · 인쇄(PDF) |
| 항목별 결과 | `#area` | 영역(8개)과 평가항목 단위 분석, 하위 협력사 |
| 협력사별 결과 | `#company` | 협력사 목록(검색·칩·정렬) → 한 협력사의 5개년 추이, **항목별 점수와 순위**, 세부항목 |

**모든 화면 공통**: 오른쪽 가장자리의 **화살표 손잡이**를 누르면 **AI 대화 패널**(LLM 대화창)이 열립니다(§9.5). **화면(디자인)과 열고 닫는 동작만** 만들고, **사내 LLM API 호출은 만들지 않습니다**(연결 자리만 둠 — 사용자가 사내 API를 받아 연결).

**핵심 요구 (사용자가 직접 요청한 것)**
1. 결과 보고: ① 전체 평균 점수와 등급별 개수·비율 ② 항목별 전년·올해 점수 증감 ③ 전년 대비 점수 변화폭이 큰 업종과 협력사 정보 ④ 부진사 ⑤ 우수사 후보 (④⑤ 기준은 사용자가 나중에 줍니다 → 지금은 **임시 기준**, 설정만 바꾸면 반영)
2. 개별 협력사 결과에서 **항목의 순위**를 알 수 있을 것 (영역 → 평가항목 → 세부항목)
3. **5개년 추이**를 볼 수 있을 것 (전체 평균, 등급 구성, 영역별, 협력사별)
4. **너무 많지 않게, 핵심만 한눈에** — 그러나 **상세한 내용도 볼 수 있을 것** → 기본은 핵심만, 상단 `상세 보기` 버튼을 켜면 세부 카드·표·목록이 함께 펼쳐짐
5. **등급 기준(확정)**: 90점 이상 **A**, 80점 이상 **B**, 60점 이상 **C**, 60점 미만 **D**
6. 오른쪽에 **패널**을 두고 **화살표를 누르면 LLM 대화창**이 열릴 것 (사내 API 연결은 별도, 지금은 디자인만)
7. 연결할 엑셀 파일은 **지금 로컬**에 있고 **나중에 서버로 올림** → 처음부터 서버에 올려도 그대로 동작하게 (§5.1)
8. 엑셀을 5년치 한꺼번에 주지 않고 **기준연도 1개년을 먼저** 준 뒤 **나머지 연도를 나중에 채움** → 1개년만으로도 전 화면이 동작하고, 과거 연도는 폴더를 추가하면 채워지게 (§6.9)
9. 올리는 곳은 **사내 GitHub** → 코드·문서만 올리고 **데이터는 올리지 않게**, 올리기 전에 막는 장치까지 (§5.2)

**우선순위 규칙**: 화면·동작이 이 문서와 목업(`종합평가_대시보드_목업.html`)이 다르면 **목업이 우선**입니다. 단 **데이터 읽기(§6)와 계산(§7)은 이 문서가 우선**입니다(목업은 가상 데이터를 쓰기 때문).

## 1. 역할

당신은 시니어 프런트엔드·데이터 엔지니어입니다. 아래 명세대로 대시보드를 **직접 구현하고, 실행해서 검증**합니다. 모호한 점이 있어도 질문으로 멈추지 말고, **가정을 기록하고(§14 양식) 진행**하세요. 단, 가정은 반드시 설정 파일에서 바꿀 수 있게 분리합니다.

## 2. 절대 규칙 (어기면 실패)

1. **오프라인·무외부통신**: CDN, 웹폰트, 원격 이미지, 분석/텔레메트리, 외부 API 호출을 쓰지 않습니다. 글꼴은 시스템 글꼴(`system-ui, -apple-system, "Segoe UI", "Malgun Gothic", "Apple SD Gothic Neo", "Noto Sans KR", sans-serif`)만.
2. **데이터 보호**: 엑셀 원본, 가공 데이터(`data.js`), 업체명은 외부로 전송하거나 저장소에 커밋하지 않습니다(`.gitignore`에 `data/` `build/` `dist/` `*.xlsx` `*.xlsm` `*.xls` `*.csv` `.env` `chat-adapter.js` 추가, §5.2). **사내 GitHub도 저장소입니다** — 접근 권한이 있으면 이력까지 볼 수 있고 한 번 올린 파일은 지워도 되살릴 수 있으므로 같은 규칙입니다. 로그·보고에는 건수와 집계 값만 적습니다. **서버에 올릴 때는 `dist/` 전체를 사내망 + 접근 권한(서버 설정) 뒤에 둡니다**(§5.1).
3. **무의존 기본**: 화면은 바닐라 JS + SVG로 만듭니다(차트 라이브러리 금지). 엑셀을 읽는 부분에만 라이브러리를 허용합니다(Python `openpyxl`/`pandas` 또는 번들한 SheetJS). 사내에서 반입 가능한 것만 쓰세요.
4. **한국어 UI**: 화면 문구는 이 문서(§9)에 적힌 그대로 씁니다. 임의로 바꾸거나 줄이지 않습니다.
5. **등급 기준(확정)**: A ≥ 90, B ≥ 80, C ≥ 60, D < 60(점). 경계값(90.0→A, 89.9→B, 80.0→B, 79.9→C, 60.0→C, 59.9→D)을 테스트로 고정합니다. 구간은 설정 한 곳(`gradeCut`)에서만 정의합니다.
6. **임시 값은 설정으로 분리**: 부진사·우수사 후보 기준, 등급 이름표(A 우수 · B 양호 · C 개선 필요 · D 부진), 영역 이름(기술·품질·대응·납기·원가·환경·재무·기타), 목표 평균 점수(85점)는 **임시**입니다. 부진사·우수사 후보에는 화면에 `임시 기준` 배지를 표시하고, 설정에서 `fixed: true`로 바꾸면 `확정 기준`으로 표시합니다.
7. **숫자 표기**: 점수 소수 1자리, 비율은 정수(단 10% 미만이고 정수가 아니면 소수 1자리), 개수는 천 단위 쉼표, 증감은 `▲ 1.3점`/`▼ 2.1점`/`– 0.0점`. 세부는 §7.1.
8. **색은 의미가 있을 때만**: 기본은 회색, **파랑 = 좋음·강조, 빨강 = 나쁨·문제**. 등급 색은 고정(A 진한 파랑 · B 연한 파랑 · C 연한 빨강 · D 진한 빨강). 색만으로 의미를 전달하지 않습니다(▲▼ 기호, 글자, 라벨 병행).
9. **차트 규칙**: 3D·파이·도넛·이중축·무지개색 금지. 막대 끝 4px 둥글게, 선 2px, 점 지름 8px 이상 + 2px 표면색 링, 격자 1px 실선, 값은 막대 끝에 직접 표기, 기준선(목표·평균·A 기준)은 점선.
10. **접근성**: 모든 차트/표 마크는 마우스 올림과 키보드 포커스 모두에서 같은 툴팁을 보여 주고, 차트가 있는 카드에는 `표` 보기 버튼(또는 표 자체)이 있습니다. 클릭 가능한 행/칩/타일은 Tab으로 이동, Enter로 실행됩니다.
11. **기본은 핵심만**: `상세 보기`가 꺼져 있을 때는 §9에서 "상세 보기에서만"으로 표시된 것을 숨깁니다.
12. **인쇄**: `결과 요약` 화면은 A4 보고서로 인쇄/PDF 저장이 됩니다(§10.8).
13. **LLM 호출 코드 금지**: AI 대화 패널은 화면과 동작만 만듭니다. LLM 주소·키·토큰·호출 코드를 프로젝트에 넣지 않고, `window.SUPPLIER_CHAT.ask`가 정의되어 있을 때만 그것을 부르며, 없으면 「API 미연결」 데모 답변을 보여 줍니다(§9.5).
14. **로컬 → 서버 이전 전제**: 지금은 로컬, 나중에 서버(정적 파일 호스팅). 서버 쪽 프로그램 없이 `dist/` 폴더만으로 동작하고, 경로는 전부 상대 경로, 엑셀 폴더·출력 폴더는 명령줄 인자로 받습니다. `dist/`의 스크립트는 일반 `<script src>`만 씁니다(§5.1).
15. **1개년부터 시작**: 기준연도 1개년(4종)만 있어도 모든 화면이 동작하고, 과거 연도는 나중에 폴더를 추가해 채웁니다. **자료가 없는 해를 가짜 값으로 메우지 않고**, 데이터를 못 읽었다고 **샘플 데이터로 대신 보여 주지도 않습니다**(§5.1 · §6.9).
16. **저장소에는 코드만**: 사내 GitHub에는 코드·문서만 올리고 데이터(엑셀 · `data.js` · 업체명이 든 파일)는 올리지 않습니다. 올리기 전에 점검 스크립트가 막습니다. 커밋은 로컬에 하되 **원격 푸시는 사용자가 확인한 뒤에만** 합니다(§5.2).

## 3. 디자인 원칙 (왜 이렇게 생겼는가)

사용자가 준 참고 이미지 3장의 원칙입니다. 새 요소를 추가할 때도 이 원칙을 따르세요.

**모양 참고(대시보드 시안)**: 짙은 남색 왼쪽 메뉴(활성 항목은 주황 배경), 연한 회색 바탕 위에 흰 카드, 맨 위에 핵심 숫자 카드(작은 추이선 포함), 그 아래 차트·표 카드 그리드.

**"작은 수정 6가지"**
1. 색을 목적 있게: 기본 회색, 강조할 것만 색.
2. 3D·파이 대신 단순한 막대/선.
3. 숫자는 반올림해서 단순하게(소수점 줄이기).
4. 모든 것이 똑같이 중요해 보이면 안 됨: 핵심 지표 하나를 크게(`평균 D/T 종합 점수`), 변화(증감)를 함께.
5. 기준선(목표·평균·전년)을 함께 보여 준다.
6. "무엇이"가 아니라 "그래서?"에 답한다: 차트마다 한 줄 해석(callout)과 다음 행동 링크.

**"대시보드 규칙 7가지"**
1. 핵심 지표를 맨 위에. 2. 관련 데이터를 묶는다(카드·섹션). 3. 카드 스타일 일관. 4. 차트 과다 금지. 5. 추이는 선/면 차트. 6. 필터·검색을 현명하게(한 줄 필터, 목록 검색·칩). 7. 행동이 분명하게(CSV 내려받기, 인쇄, 명단 보기 버튼).

**이 프로젝트의 추가 원칙**
- 화면마다 **결론 한 줄**을 먼저 보여 줍니다(결과 요약 맨 위 3줄, 협력사 상세의 callout).
- **핵심 → 상세** 2단계: 기본 화면은 핵심, `상세 보기`/펼치기/표 보기로 세부.
- 모든 카드 제목 옆 `i` 버튼에 마우스를 올리면 그 카드가 쓰는 **엑셀 컬럼명**이 보입니다(출처 추적용).

## 4. 진행 방식 (M0 → M9, 순서대로 · M10은 선택)

각 단계가 끝나면 **10줄 이내로 보고**(한 일 · 검증 결과 · 가정)하고 **멈추지 말고 다음 단계로** 갑니다. 단계의 완료 기준(DoD)을 못 채우면 고친 뒤 넘어갑니다.

### M0. 환경 점검 (코드 작성 금지)
- 확인: OS, Python(버전 · `openpyxl`/`pandas` 유무), Node(버전), 브라우저(Chrome/Edge 버전), Playwright 사용 가능 여부, 패키지 설치 가능 여부(사내 미러).
- 확인(저장소): 사내 GitHub 원격 주소(있다면)·기본 브랜치·푸시 권한, Pages·Actions 사용 가능 여부 — 모르면 「미확인」으로 적고 기본 방식(§5.2: 코드만 올림, 데이터 제외)으로 진행합니다.
- 확인(데이터 위치): 엑셀이 지금 어디 있는지(로컬 폴더 경로 — 한글·공백 포함 여부, 네트워크 드라이브 여부)와 연도 폴더가 몇 개인지(1개년만 있어도 시작 — §6.9). 나중에 서버로 올릴 예정이므로 경로는 코드에 넣지 않고 명령줄 인자로 받습니다(§5.1).
- **엑셀 연동 방식 선택 규칙** (UI는 어느 쪽이든 똑같아야 함)
  - (A) Python + openpyxl 가능 → `tools/build_data.py`가 엑셀을 읽어 `dist/data.js` 생성 (**권장**)
  - (B) Node 가능 → `tools/build_data.mjs` + `vendor/`에 번들한 SheetJS
  - (C) 둘 다 불가 → 브라우저에서 파일을 직접 선택해 읽기(SheetJS를 `vendor/`에 포함). 이때만 사이드바 아래에 `데이터 불러오기` 버튼을 추가합니다.
- 산출: 선택 결과와 이유(10줄 이내). 이후 질문 없이 진행합니다.

### M10. (선택) 사내 GitHub Pages로 발행 — 사용자가 정책 확인을 알려 준 경우에만
- 시작 전에 사용자에게 한 줄로 묻습니다: 「데이터(`data.js`)를 사내 GitHub의 발행 전용 브랜치에 올려도 되고, Pages 보기 권한을 저장소 접근 권한자로 제한할 수 있나요?」 **둘 다 '예'일 때만** 진행하고, 아니면 건너뜁니다(§5.2의 1·2번 방식). 묻지 않고 진행하지 않습니다.
- 발행 전용 브랜치 `gh-pages`(또는 별도 비공개 저장소)에만 `dist/`(data.js 포함)를 올립니다. `main`·기능 브랜치에는 절대 올리지 않습니다.
- 올릴 때마다 **이력 없이 덮어씁니다**: 임시 폴더에서 `dist/` 내용만으로 새 저장소(커밋 1개)를 만들어 `gh-pages`에 강제 푸시 → 옛 데이터가 이력에 쌓이지 않습니다. 강제 푸시는 `gh-pages` 한 곳에만, 실행 전에 원격 주소·브랜치·올릴 파일 목록을 보여 주고 사용자 확인을 받으며 **기본은 모의 실행(`--dry-run`)** 입니다. 올리는 파일은 `index.html` `styles.css` `settings.js` `app.js` `data.js` `.nojekyll`뿐인지 확인합니다.
- Pages 주소는 하위 경로(`…/<저장소>/`)이므로 §5.1 규칙(상대 경로·해시 이동)이 그대로 맞고, `index.html`과 같은 폴더에 `.nojekyll`을 둡니다. 데이터를 새로 올릴 때마다 `data.js?v=…`로 캐시를 피합니다.
- 산출: `tools/publish_pages.(py|sh)` + README 5줄. **DoD**: 모의 실행이 올릴 파일 목록을 정확히 보여 주고, 실제 푸시는 사용자 확인 뒤에만 일어난다. 끝나면 최종 보고(§15-11)에 결과를 덧붙입니다.

- **실행(지금, 로컬)**: `python tools/build_data.py` → `dist/index.html`을 브라우저로 열기(더블클릭, `file://`). 서버가 필요 없어야 합니다.
- **빌드가 하는 일**: ① 엑셀 → `dist/data.js` + `dist/data_check.html` ② `src/`의 정적 파일과 `config/settings.js`를 `dist/`로 복사하고, `index.html`의 `__BUILD__`를 빌드 시각으로 바꿔 `data.js?v=…`로 불러오게 함(갱신 뒤 캐시 때문에 옛 데이터가 보이는 일을 막음). 그래서 **`dist/` 폴더 하나만 옮기면 어디서나 동작**합니다.
- **데이터 로드 방식**: `dist/index.html`이 `<script src="data.js?v=…"></script>`로 `window.__SUPPLIER_DATA__`를 읽습니다(`file://`에서 `fetch`가 막히기 때문에 JSON 대신 JS 파일을 씁니다). 읽는 자리는 `loadData()` 한 곳이며 규칙은 §5.1입니다. **샘플 모드는 주소에 `?sample=1`이 있을 때만** 켜집니다(§12).
- **엑셀 파일 이름은 신경 쓰지 않습니다**. 파일 종류는 헤더로 판별합니다(§6.2). 연도는 폴더 이름(숫자 4자리)으로 정합니다.
- 갱신: 엑셀을 `data/<연도>/`에 넣고 `build_data`를 다시 실행하면 끝입니다(연도 폴더는 1개만 있어도 되고 나중에 하나씩 추가 — §6.9).
- 사이드바 아래 문구: `최종 갱신 {data.js 생성 시각}` / `데이터: 사내 엑셀 4종 ({가장 이른 연도 폴더}~{기준 연도})`(연도 폴더가 하나면 `({기준 연도})`) (샘플 모드: `데이터: 가상 샘플 (목업)`).

### 5.1 지금은 로컬 · 나중에 서버 (처음부터 이 전제로 만듭니다)

엑셀과 화면은 **지금 내 PC(로컬)** 에서 쓰고, **나중에 사내 서버에 올려** 여러 사람이 봅니다. 서버 쪽 프로그램은 만들지 않습니다 — **`dist/` 폴더(정적 파일)만 올리면 되게** 만듭니다.

| 구분 | 지금 (로컬) | 나중 (서버) | 만들 때 지킬 것 |
|---|---|---|---|
| 열기 | `dist/index.html` 더블클릭(`file://`) | 서버 주소(`http(s)://…`) | 두 방식에서 **같은 파일이 똑같이** 동작 (코드 수정 없음) |
| 엑셀 위치 | 프로젝트의 `data/<연도>/` | 서버의 엑셀 폴더(공유 폴더 등), 또는 계속 로컬에서 변환 | 경로는 **명령줄 인자**: `build_data --data-dir <엑셀 폴더> --out <출력 폴더>` (기본 `./data` `./dist`). 코드·설정에 절대 경로 금지 |
| 데이터 갱신 | 엑셀 교체 → `build_data` → 새로 고침 | ① 로컬에서 빌드해 `dist/`를 서버에 복사 ② 서버에서 `build_data`를 예약 실행(작업 스케줄러·cron) | 갱신은 언제나 `dist/data.js` 교체로 끝 |
| 설정 | `config/settings.js` | 같음 | 서버 전용 설정 파일 없음 |
| AI 대화 | 어댑터 없음 → 데모 답변 | `chat-adapter.js`가 **같은 서버의 중계 주소**만 호출 | §9.5-5 |

**지킬 규칙**
1. **상대 경로만**: `./styles.css`처럼 씁니다. 절대 경로·`C:\`·사용자 폴더 이름·`localhost` 주소를 코드에 넣지 않습니다. 서버의 하위 주소(`https://서버/dash/`)에 올려도 되도록 화면 이동은 해시(`#report`)만 씁니다.
2. **일반 `<script src>`만**: `dist/`에서는 ES 모듈(`type="module"`, `import`)과 `fetch`를 기본 경로에서 쓰지 않습니다(`file://`에서 막힘). `src/`는 모듈로 나눠도 되지만 빌드가 `dist/app.js` **한 파일**로 합칩니다. 설정 파일도 `export default` 대신 `window.SUPPLIER_SETTINGS = {…}`(§11).
3. **UTF-8 명시**: 파일 읽기·쓰기는 모두 `encoding='utf-8'`(한국어 Windows 기본 인코딩 cp949에서 글자가 깨지지 않게). `data.js`는 BOM 없는 UTF-8.
4. **경로·파일 이름**: 한글·공백이 있어도 동작(`pathlib`/`path.join` 사용, 셸 명령 문자열 이어붙이기 금지). 엑셀을 열어 둔 상태에서 생기는 `~$…` 임시 파일은 건너뛰고 점검 리포트에 기록. 수식 셀은 **저장된 값**으로 읽습니다(`openpyxl`은 `data_only=True`, `read_only=True`).
5. **데이터 읽는 자리는 한 곳 `loadData()`** — 우선순위: ① `window.__SUPPLIER_DATA__`(`data.js`를 읽은 경우 — 로컬·서버 공통) ② 없고 `settings.data.url`이 있으면 `fetch`로 JSON(서버용 선택 기능 — `file://`에서는 동작하지 않으므로 로컬 테스트는 `python -m http.server`) ③ 없고 주소에 `?sample=1`이 있으면 내장 샘플(§12) ④ 그 외 → **오류 화면**. 화면은 데이터를 다 읽은 뒤에 시작합니다(`boot()`).
   - `fetch` 모드에서 읽는 동안: 본문 자리에 「데이터를 불러오는 중입니다…」
   - **오류 화면**(`#empty` 자리, 점선 상자): 제목 「데이터를 불러오지 못했습니다」 + 한 줄 원인. `data.js` 방식: 「`data.js`가 없거나 읽을 수 없습니다. `build_data`를 실행했는지, `data.js`가 `index.html`과 같은 폴더에 있는지 확인하세요.」 / `fetch` 방식: 「`{주소}`를 읽지 못했습니다({상태 코드 또는 오류}). 서버 주소와 접근 권한을 확인하세요.」 + 버튼 「다시 시도」. **데이터를 못 읽었다고 샘플 데이터로 대신 보여 주지 않습니다**(가짜 데이터가 진짜처럼 보이는 사고 방지).
6. **서버에 올릴 때(데이터 보호)**: `data.js`는 정적 파일이라 주소를 알면 누구나 받을 수 있습니다. **`dist/` 전체를 사내망 + 접근 권한(서버의 SSO·Basic 인증 등) 뒤에** 두세요 — 이 프로젝트는 로그인 기능을 만들지 않습니다. 외부 공개 금지, 저장소 커밋 금지는 그대로입니다.
7. **서버 설정 메모**(README에 적을 것): `.js`는 UTF-8로 제공, `data.js`는 gzip 허용(수 MB 규모), `index.html`·`data.js`는 `Cache-Control: no-cache`. 서버 종류(IIS·nginx·Apache 등)가 정해지면 그 서버용 3줄 절차를 README에 추가합니다.


### 5.2 사내 GitHub (코드는 올리고, 데이터는 올리지 않습니다)

코드를 올리고 받는 곳은 **사내 GitHub**입니다. 사내 GitHub라도 저장소를 볼 수 있는 사람은 **이력까지 전부** 볼 수 있고, 한 번 올린 파일은 지워도 이력에서 되살릴 수 있습니다. 저장소 접근 권한과 데이터 접근 권한은 다르므로 **업체명·점수가 든 파일은 저장소에 올리지 않습니다**.

|---|---|---|
| 코드·문서 | `src/` `tools/` `tests/` `config/settings.js` `README.md` `.gitignore` `.githooks/` | — |

| 연결 정보 | `src/chat-adapter.example.js`(뼈대) | `chat-adapter.js` · `.env` · 키·토큰 |

**막는 장치 (처음부터 만듭니다)**
1. `.gitignore`: `data/` `build/` `dist/` `*.xlsx` `*.xlsm` `*.xls` `*.csv`(단 `!tests/fixtures/*.csv`) `.env` `chat-adapter.js` `node_modules/` `__pycache__/` `.venv/`

3. 점검 스크립트는 자동 시험으로 고정합니다(§13.1-12). 최종 보고(§15)에는 `git ls-files` 요약(데이터 파일 0개)을 적습니다.

**작업 규칙**
- 기능 브랜치에서 작업하고 `main`에 직접 올리지 않습니다(사내 규칙이 있으면 그것을 따름). 커밋 메시지는 한국어로 「무엇을 · 왜」 한 줄.

### 6.2 헤더 읽기 · 파일 종류 판별 · 정규화

1. **헤더 행 찾기**: 각 시트의 위쪽 10행에서 `협력사 코드`가 들어 있는 행을 **컬럼 행**으로 씁니다. 그 바로 위 행에 그룹 이름(`평가대상사`, `평가결과`, `전년도 결과`, `평가항목`, `세부항목`)이 있으면 **그룹 행**입니다. 병합 셀은 왼쪽 값을 오른쪽 빈 칸으로 채워(forward-fill) 읽습니다.
2. **컬럼 키**: 그룹이 `평가결과`·`전년도 결과`·`평가항목`·`세부항목`이면 `그룹.컬럼`(예: `전년도 결과.배점`), `평가대상사`이거나 그룹이 없으면 컬럼 이름만 씁니다. 같은 이름이 겹치면(①의 `배점` 등) 반드시 그룹으로 구분합니다. **매핑 조회 순서**: ① `그룹.컬럼` 정확 일치 → ② 그룹을 뺀 컬럼 이름이 그 파일 안에서 **유일하면** 그 컬럼(예: ④의 `평가항목 코드`는 그룹 `평가항목` 아래에 있어도 이름만으로 찾음). 부록 C의 `[평가결과] 배점` 표기는 키 `평가결과.배점`을 뜻합니다.
3. **이름 정규화(비교용)**: 모든 공백·줄바꿈·NBSP 제거, 전각→반각(NFKC), 소문자. 그래서 `환산 평점` = `환산평점`, `D/T 종합 점수` = `D/T종합점수`로 인식합니다.
4. **파일 종류 자동 판별**(파일 이름 무시, 이 순서로 검사): 컬럼에 `세부항목 코드`와 `세부항목 값`이 있으면 ④ → `G/T 코드`와 `T-환산점수`가 있으면 ② → `평가항목 코드`와 `환산평점`이 있으면 ③ → 그룹 `전년도 결과`가 있으면 ①. 어느 것도 아니면 건너뛰고 점검 리포트에 기록.
5. **연도**: 파일이 들어 있는 폴더 이름(숫자 4자리). 없으면 `settings.baseYear`.
6. **시트**: 숨김 시트 제외. 판별되는 시트가 여러 개면 같은 형식으로 보고 행을 합칩니다.
7. **행 거르기**: 빈 행, `협력사 코드`가 빈 행, 첫 칸이 `합계`/`소계`인 행은 제외.
8. **필수 컬럼**(종류별)이 없으면 **오류로 멈추고** 어떤 이름이 없는지, 시트에서 가장 비슷한 이름이 무엇인지 알려 줍니다. 컬럼 이름이 사내 표기와 다르면 `settings.columns`의 동의어 목록에 추가하게 안내합니다(부록 C의 `COLUMNS`가 기본 매핑).

### 6.3 값 정규화

| 종류 | 규칙 |
|---|---|
| 숫자 | 쉼표·공백 제거, `12.5%` → 12.5, `-`/빈 칸/`N/A`/엑셀 오류 → null. 숫자로 읽힌 코드(`협력사 코드` 등)는 **문자열**로(앞자리 0 보존, `.0` 제거) |

### 6.5 변환 규칙 (엑셀 → 모델)

**협력사 단위**: `(D/T 코드, 협력사 코드)` 한 쌍 = 협력사 1개(`key`). 같은 `협력사 코드`가 서로 다른 `D/T 코드`에 있으면 **서로 다른 협력사**로 보되 점검 리포트에 경고. *(가정 A1)*

**대표 행**: 한 협력사의 ②행들 중 `D/T 등급 반영비중-거래비중`이 가장 큰 행(동률이면 먼저 나온 행). 대표 행에서 `org`, `generalOrg`, 세부 평가단위, 평가조직 등급 등을 가져옵니다. *(가정 A2)*

| 모델 필드 | 엑셀 출처 | 규칙 |
|---|---|---|
| `code` `name` | 모든 파일 | `협력사 코드`, `협력사명` |
| `rep` `dt` `gt` | ② | `대표코드`, `D/T 코드`, `G/T 코드` |
| `region` `regionCode` `inout` `unit` `group` `confirmed` | ① (없으면 ②) | `권역명` `권역 코드` `내/외자` `평가단위` `세부업종그룹` `협력사 확인` |

### 6.6 5개년 이력 (`hist`)

- `years = [기준연도−4, …, 기준연도]`(자료가 없는 해도 `years`에는 들어갑니다). 기준연도 = 엑셀 폴더 아래 **①②③④가 모두 있는** 가장 큰 연도(또는 `settings.baseYear`, 화면의 `평가 연도` 필터로 바꿀 수 있음 — 선택한 해를 기준으로 5개년을 다시 계산).
- `hist[Y].dt` = **Y년 폴더의 ① `[평가결과] D/T 종합 점수`**, `hist[Y].grade` = 같은 행의 `D/T 최종 등급`, `hist[Y].areas[코드]` = Y년 ②의 `{코드}-환산점수`(§6.5의 가중 평균).
- **Y년 폴더에 ①이 없으면**: **Y+1년 폴더 ①의 `[전년도 결과]`**(`D/T 종합 점수`·`D/T 최종 등급`)로 `hist[Y].dt`·`grade`를 대신하고, 그것도 없으면 `null`. 영역(`hist[Y].areas`)은 Y년 ②에서 오며, ②가 없으면 Y = 기준연도−1일 때만 `prevAreas`로 대신하고 그 밖에는 모두 `null`.
- **읽는 파일**: 기준연도는 ①②③④ 모두(없으면 오류로 멈춤). **과거 연도는 ①(필수)·②(선택)만** 읽고, 과거 연도의 ③④는 있어도 읽지 않습니다(점검 리포트에 `미사용`으로만 기록). 1개년만 먼저 주고 나머지를 채우는 방법은 §6.9.
- 협력사가 그해 평가 대상이 아니면 `hist[Y] = null`(신규 협력사). 화면에서는 선이 끊기고 점이 없습니다.
- **코호트 원칙**: 추이(평균 점수, 등급 구성, 영역별)는 **현재 필터에 걸린 '기준연도 평가 협력사'들의 과거 이력**입니다. 연도마다 평가 대상이 달라도 같은 협력사 집단을 따라가므로, 화면에는 연도별 협력사 수를 함께 보여 줍니다(표 보기의 `평가 협력사` 열). *(가정 A8)*

### 6.7 데이터 점검 리포트 (`dist/data_check.html` + 콘솔 요약)

빌드할 때마다 만들고, 화면 사이드바 아래에 `데이터 점검` 링크(새 탭)로 연결합니다. 포함 항목:
1. 연도별 파일 4종의 **파일 이름 · 시트 · 행 수 · 판별 결과**
2. 컬럼 매핑 결과: 찾은 컬럼 / 못 찾은 필수 컬럼 / 동의어로 매칭된 컬럼
3. 협력사 수(연도별), 신규 협력사(전년 없음) 수, 같은 `협력사 코드`가 여러 `D/T 코드`에 있는 건수
4. ①↔②↔③ **키 불일치** 건수(한쪽에만 있는 협력사)
5. 거래비중 합 ≠ 100±0.5 인 협력사 수
6. **등급-점수 불일치**: 엑셀의 `D/T 최종 등급`이 §7.2 구간과 다른 협력사 수(등급 조정 대상 제외)와 예시 5건
7. 점수 범위 이탈(0~100 밖), 등급 값 이상(`A/B/C/D` 외)
8. 환산평점 스케일 판정(§6.3), `환산평점 ≠ 평점/배점×100` 인 행 비율
9. 미적용·무실적 비율, 항목 누락 건수
10. `분류체계 → 영역` 매핑 결과와 미분류 값
11. **연도별 자료 현황**: 연도 · ①②③④ 각각 `있음`/`없음`/`미사용`(과거 연도의 ③④) · 협력사 수 · 상태(`전체`/`점수·등급만`/`전년도 결과로 보충`/`없음`) · 다음에 채우면 좋은 것(예: 「2024년 ① 추가 → 5개년 점수 추이 완성」)

### 6.8 예외 처리 (신규 협력사 · 빈 값)

- `prev == null`인 협력사: 전년 비교(증감·등급 이동·순위 변화)에서 **제외**하고, 표에는 `–`로 표시합니다. 전년 값의 평균·비율은 **전년 값이 있는 협력사만**으로 계산하고, 증감은 같은 협력사 쌍으로 계산합니다. 이때 카드 하단에 `전년 비교는 전년 평가가 있는 N개사 기준 (신규 M개사 제외)` 한 줄을 추가합니다(M > 0일 때만).
- 영역/평가항목 값이 null이면 평균·순위 계산에서 제외합니다.
- `dtScore`가 없는 협력사는 목록에서 제외하고 점검 리포트에 기록합니다.


### 6.9 연도를 단계적으로 채우기 (1개년 먼저 → 나머지는 나중에)

엑셀을 5년치 한꺼번에 준비하기 어려우면 **기준연도 1개년만으로 시작**하고 과거 연도를 나중에 하나씩 채웁니다. 처음부터 이렇게 동작하게 만듭니다.

| 단계 | 연도 폴더에 넣는 파일 | 화면에서 되는 것 |
|---|---|---|
| ① 시작 (필수) | **기준연도** 폴더에 4종 모두 (①②③④) | **모든 화면**: 평균·등급, 전년 비교(①의 `[전년도 결과]`), 항목 순위, 부진사·우수사 후보. 5개년 추이는 **2점**(전년·올해) |
| ② 과거 연도 (권장) | 과거 연도 폴더에 **① 만** | 평균 점수·등급 구성·협력사별 점수 추이의 점이 늘어남 |
| ③ 영역 추이 (선택) | 같은 과거 연도 폴더에 ② 추가 | 영역별 5개년 추이가 채워짐 |
| 불필요 | 과거 연도의 ③④ | 있어도 읽지 않음 (항목 전년 값은 기준연도 ③의 `이전 환산평점`으로 충분) |

- **채우는 순서**: 최근 연도부터(기준−1, 기준−2 …). 폴더 하나를 추가할 때마다 `build_data`를 다시 실행합니다. 중간 연도가 비어도 되고, 폴더가 하나뿐이어도 오류가 아닙니다.
- **격년으로 줘도 됩니다**: Y 폴더 ①의 `[전년도 결과]`가 Y−1의 점수·등급으로 쓰이므로(§6.6), ①을 기준연도·기준−2·기준−4 세 곳에만 넣어도 점수·등급 5개년이 채워집니다(영역 추이는 ②가 있는 해만).
- **한 파일씩 먼저 점검**: `build_data --check <엑셀 파일>` — 그 파일의 시트·헤더 행·판별 종류·컬럼 매핑·누락된 필수 컬럼만 출력하고 변환·저장은 하지 않습니다. 새 연도 파일을 넣기 전에 돌려 봅니다.
- **`평가 연도` 필터**에는 ①②③④가 **모두 있는 연도**만 나옵니다(1개년이면 선택지 하나 — 목업과 같음). ①만 있는 과거 연도는 추이에만 쓰이고 기준연도로는 고를 수 없습니다.
- **화면 규칙** (자료가 없는 해 = 어느 협력사에도 `hist[연도]`가 없는 해)
  - 선·점·막대를 그리지 않되 가로 축 눈금(연도 5개)은 그대로 남깁니다. 툴팁은 「자료 없음」, `표 보기`의 값 칸은 「–」.
  - 등급 구성(`#rp-gtrend`)의 그 해 줄은 막대 대신 회색 글 「자료 없음」. callout 「A등급 비율 {첫연도}년 → {기준연도}년」의 첫연도는 **자료가 있는 가장 이른 해**이고, 비교할 해가 하나뿐이면 callout을 만들지 않습니다.
  - 자료가 있는 해가 5개 미만이면 `#rp-trend` `#rp-gtrend` `#ar-trend` `#co-trend`의 **제목 옆에** `warn` 배지 「자료 {n}/5개년」(툴팁 「{없는 연도} 엑셀을 추가하면 채워집니다」)을 붙이고, 5개가 다 있으면 배지는 없습니다. `n` = `years` 중 어느 협력사에든 `hist[연도]`가 있는 해의 수. 스파크라인은 점이 2개 미만이면 「–」(기존 규칙).
- **점검 리포트**(§6.7-11)에 연도별 자료 현황과 「다음에 채우면 좋은 것」을 적습니다.

## 7. 계산 규칙 (화면 숫자의 기준)

아래의 `L`은 **현재 필터를 통과한 협력사 집합**(필터 7개, §10.2)입니다. 모든 카드는 같은 `L`로 계산해 숫자가 서로 맞아야 합니다. 평균은 null을 빼고 계산합니다.

### 7.1 숫자 표기
| 함수 | 규칙 | 예 |
|---|---|---|
| `n(v)` | 반올림 정수, 천 단위 쉼표(ko-KR) | 1,248 |
| `sc(v)` | 소수 1자리로 반올림, 항상 1자리 | 82.9 · 5.0 |
| `pct(v)` | `r = round(v×10)/10`. `abs(r) < 10`이고 정수가 아니면 소수 1자리, 아니면 정수. 끝에 `%` | 7.1% · 9% · 17% · 0.4% |
| `sgn(v, d=1)` | 부호 + 절댓값(d자리). 양수 `+`, 음수 `−`(U+2212), 0 `±` | +1.3 · −2.1 · ±0.0 |
| `delta(v, unit, {goodUp=true, digits=1, suffix})` | `r = round(v×10^digits)/10^digits`. 모양: `▲ 1.3점`(r>0) / `▼ 2.1점`(r<0) / `– 0.0점`(r=0). **색**: r=0 회색, `(r>0) === goodUp`이면 파랑(좋음), 아니면 빨강. `suffix`는 연한 회색 글자로 뒤에 붙음(예: `전년 대비`) | ▲ 1.3점 전년 대비 |

- 비율 증감은 `%p` 단위(`▲ 3.0%p`). 등급별 개수 증감은 단위 `개사`, `digits=0`.
- `goodUp=false`인 곳: `C·D 등급 비율`, 등급 `C`·`D`의 개수 증감.

### 7.2 등급
- `gradeOf(점수)` = 점수 ≥ A기준(90)이면 `A`, ≥ B기준(80)이면 `B`, ≥ C기준(60)이면 `C`, 아니면 `D`. **엑셀에 등급 값이 있으면 그 값이 우선**이고, 없을 때만 계산합니다.
- 등급 순서 `GI`: A=0, B=1, C=2, D=3. `move = GI[전년 등급] − GI[올해 등급]` → **양수 = 상승, 음수 = 하락**. `2단계 이상 하락` = `move ≤ −2`.
- `A 승급 후보` = `A기준 − 5 ≤ D/T 종합 점수 < A기준` (기본 85.0~89.9점). 폭 5는 `settings.nearA`.
- `C·D 등급` = `GI ≥ 2`.
- 등급 칩 글자색: 채움색의 밝기(상대 휘도) 0.36 초과 → `#0b0b0b`, 이하 → `#ffffff` (부록 D `inkOn`).

### 7.3 집계 기본
- `areaAvg(L, 코드, key)` = `L` 중 `x[key][코드].conv`가 null이 아닌 값의 평균 (`key`: `areas`=올해, `prevAreas`=전년).
- `yearAvg(L, f)` = 연도별로 `hist[y]`가 있는 협력사의 `f(hist[y])` 평균. 없으면 null.
- `yShare(등급들)` = 연도별로 `hist[y]`가 있는 협력사 중 등급이 `등급들`에 속하는 비율(%).
- `itemStats(L, 영역)` = 그 영역의 평가항목별 `{ n(적용 수), value = 평균(r)×100, prev = 평균(pr)×100, na(미적용 수), np(무실적 수) }` — `na`나 `np`인 협력사는 평균에서 제외하고 개수만 셉니다.
- 전년 평균/비율은 §6.8대로 **전년 값이 있는 협력사만**으로 계산합니다.

### 7.4 상태 판정 (색·문구)
- **영역 타일**: `영역평균들의 평균 = mean`, `d = 영역 올해 평균 − mean`. `d ≤ −2` → 빨강 글씨 `평균보다 {abs(d):1자리} 낮음`, `d ≥ 2` → 회색 `평균보다 {d:1자리} 높음`, 그 외 회색 `평균 수준`.
- **평가항목 막대**(항목별 결과): 항목 평균 `≤ 선택 영역 평균 − 2` → 빨강(`bad`), 그 항목 중 가장 낮은 것에만 태그 `최저`. 해당 없으면 모두 회색.
- **70점 기준(`lowLine`)**: `영역 환산점수 < 70`을 `약함`으로 보고, 비율(`영역별 70점 미만 %`)·명단에 씁니다(`settings.lowLine`).
- `등급 구성 개선/악화/비슷`(결과 요약 2번째 줄): `개선` = A 비율이 올랐고 C·D 비율이 오르지 않음, `악화` = A 비율이 내렸고 C·D 비율이 올랐음, 그 외 `비슷`.

### 7.5 순위
- `ranker(값들)`: null을 뺀 값들을 큰 순으로 정렬. `rank = 1 + (v보다 큰 값의 개수)`(**동점은 같은 순위**), `total` = null 아닌 값 수, `top = rank/total×100`.
- `rankText`: `top ≤ 50` → `상위 {pct(max(top, 0.1))}`, 아니면 `하위 {pct(max((total−rank+1)/total×100, 0.1))}`.
- `rankCell`: `{rank}위` + 막대(채움 = `1 − (rank−1)/total`) + `rankText`. **색**: `top ≤ 20` 파랑, `top > 80` 빨강, 그 외 회색.
- 순위는 모두 **`L` 안에서** 계산: 협력사 전체(`dtScore`), 영역별(`areas[코드].conv`), 평가항목별(`items[i].r`, 미적용·무실적은 제외), 연도별(`hist[y].dt`, 그해 평가 대상 중).
- 협력사 상세의 "가장 높은 순위/가장 낮은 순위 영역" = 영역 순위(rank)가 가장 작은/큰 영역.

### 7.6 변화·TOP 목록
- 협력사 점수 변화 `d = dtScore − prev.dtScore` (전년 있는 협력사만). **상승 TOP N**: `d` 내림차순, **하락 TOP N**: 오름차순. N = 5 (상세 보기 10).
- **가장 크게 변한 영역**: 영역별 `|올해 conv − 전년 conv|`(둘 다 있는 영역)이 가장 큰 영역. 변화가 0이면 표시하지 않음. 표시: `{영역명(코드)} {sgn(d)}`.
- **업종 타일**(세부업종그룹): 그룹마다 `n`, `cur = 평균 dtScore`, `d = 평균(dtScore − prev.dtScore)`, `years = yearAvg(그룹 협력사, dt)`. `d` 내림차순 정렬. 첫 타일에 `변화 최대`(파랑 태그), 마지막 타일에 `변화 최소`(회색 태그, 타일이 2개 이상일 때).
- **업종(세부)**(상세 보기): `industry` 값별, 협력사 10개사 이상만. `d` 내림차순 상위 5(`변화 큰 업종 5`)와 하위 5를 뒤집어서(`변화 작은 업종 5`).
- **평가조직별**(상세 보기): `L`의 모든 `evals` 행을 평가조직별로 모아 `n`(행 수), `평균 = 평균(e.score)`, `전년 대비 = 평균(e.score − 협력사.prev.score)`(전년 있는 것만), 등급 구성(`e.grade` 개수), `부진사`/`우수사 후보` 수(그 행의 협력사가 해당되는 건수).

### 7.7 부진사 · 우수사 후보 (임시 기준 → 설정으로 교체)
- 판정: 규칙 목록 `rules`와 `mode`로 결정. `mode='any'`는 **하나라도 해당**, `mode='all'`은 **모두 해당**.
- **임시 기준**
  - 부진사 (`any`): ① `D등급 (60점 미만)` — 등급이 D ② `전년 대비 2단계 이상 하락` — `move ≤ −2`
  - 우수사 후보 (`all`): ① `A등급 (90점 이상)` ② `전년 대비 등급 하락 없음` — `move ≥ 0` ③ `등급 조정·거래중단 예정 아님` — 조정 대상 아님 **그리고** 거래중단예정일 없음
- 정렬: 부진사는 점수 **낮은 순**, 우수사 후보는 점수 **높은 순**.
- 설정은 **선언형**으로 둡니다(§11): 사용자가 기준을 주면 `settings.criteria`의 `rules`만 바꾸고 `fixed: true`로 바꿉니다.

### 7.8 목록 칩 10개 (협력사별 결과)
`전체` · `등급 상승`(move>0) · `등급 하락`(move<0) · `2단계 이상 하락`(move≤−2) · `부진사` · `우수사 후보` · `A 승급 후보` · `C·D 등급`(GI≥2) · `등급 조정 대상` · `거래중단 예정`(거래중단예정일 있음). 칩 숫자 = `L` 중 해당 수.

### 7.9 정렬 5종 · 검색 · 사유 배지
- 정렬: `D/T 종합 점수 높은 순`(기본, `score_desc`) · `D/T 종합 점수 낮은 순`(`score_asc`) · `점수 상승 큰 순`(`up`: `dtScore − prev.dtScore` 내림차순) · `점수 하락 큰 순`(`down`: 오름차순) · `협력사명 순`(`name`, `localeCompare`). 전년 없는 협력사는 상승/하락 정렬에서 맨 뒤.
- 검색: 협력사명 또는 협력사 코드에 입력 글자가 **포함**(대소문자 무시). 입력 후 180ms 뒤 반영.
- **사유 배지**(목록 `비고` 열): `move ≤ −2` → `{n}단계 하락`(빨강, ↓ 아이콘), 그 외 `move < 0` → `등급 하락`(빨강), `D` → `D등급`(빨강), 조정 대상 → `등급 조정`(주황), 거래중단예정일 있음 → `거래중단 예정 MM-DD`(주황).

  - 줄: `delta(점, 「전년 대비」)` + (첫 평가 연도가 기준연도가 아니면) ` · ` + `delta(점, 「{첫연도}년 대비」)`
  - 줄: `rankCell`(전체 순위) + 「/ {N}개사」
  - 줄: 「평가 점수 {sc} = 일반항목 환산점수 {sc} + 가산점 {sc}」

**C4. 카드 2개 한 줄**
- **`#co-trend`** (span-4, `표`) 「5개년 추이」 · 부제 「점 위 = 그해 등급 · 회색 = 전체 평균」 · (i) 「연도별 1번 파일 D/T 종합 점수·D/T 최종 등급」
  - 범례: 파랑 선 `{협력사명}` · 회색 선 「전체 평균」 · 점선 「A 기준 {90}」
  - 선 차트: 메인(파랑, 협력사의 연도별 D/T 종합 점수, 평가 없는 해는 끊김) + 보조(회색, `yearAvg(L, dt)`) + 점선 기준 「A 기준 {90}」 + **각 점 위에 그해 등급 칩**
  - 표 보기 열 「연도」「D/T 종합 점수」(없으면 「평가 없음」)「등급」「그해 순위」(「{rank} / {total}」)「전체 평균」
- **`#co-rank`** (span-8) 「항목별 점수와 순위」 · 부제 「영역을 누르면 평가항목 순위, 평가항목을 누르면 세부항목」 · (i) 「{영역}-환산점수 (2번), 평가항목 환산평점·이전 환산평점 (3번), 세부항목 (4번)」
  - **펼침 표** 열 「영역 / 평가항목」「점수」「전체 평균」「순위」「전년 대비」「5개년」
    - 영역 줄: `{영역명(코드)}` + 태그 「최고 순위」(파랑) 또는 「최저 순위」(빨강)(가장 높은/낮은 순위 영역 각 한 곳) · **점수(굵게)** · 전체 평균(`L`의 영역 평균) · `rankCell` · `delta(올해−전년)`(전년 없으면 「–」) · 스파크라인(이 협력사의 5개년 영역 점수)
    - 평가항목 줄: 항목명(+ 미적용/무실적이면 회색 태그 「미적용」/「무실적」) · 환산평점(`r×100`, 제외 항목은 「–」) · 항목 전체 평균 · `rankCell`(항목 순위, 제외 항목 「–」) · `delta((r−pr)×100)` · (5개년 칸 비움). **행을 누르면 그 항목이 선택**(다시 누르면 해제)되고 표 아래에 세부항목 패널이 열립니다.
  - **세부항목 패널**(위쪽 구분선): 굵은 글 「세부항목 — {항목명}」 + 작은 버튼 「닫기」 / 줄 「배점 {sc} · 평점 {sc} · 환산 평점 {sc} · 전체 평균 {sc}」(제외 항목은 평점·환산 평점 「–」) / 제외 항목이면 글 「배점 계산에서 제외된 항목입니다.」, 아니면 ④의 세부항목 카드 목록: 이름(굵게) · 오른쪽 값(굵게) · 아래 회색 「{세부항목 코드} · 세부 등록 주체: {주체}」
  - **하단**: 글 「순위 = 필터 적용 범위 안에서 높은 점수 순 · 상위 20% 파랑, 하위 20% 빨강」 + 「이 협력사 항목 내려받기」 → `{협력사명}_항목별순위.csv` (헤더 `구분, 영역/평가항목, 점수, 전체 평균, 순위, 대상 수, 전년 대비`, 구분 값 「영역」「평가항목」)

**선택된 협력사**: 다른 화면에서 협력사를 눌러 들어오면 그 협력사. 처음 들어오면 **목록의 첫 협력사**(샘플 모드는 목업과 같게 「평가조직이 3곳이고 등급이 하락한 첫 협력사」, 없으면 목록 첫 협력사). 목록에서 다른 행을 누르면 `선택 협력사`가 바뀌고, 세부항목 선택과 영역 펼침은 초기화됩니다.

**상세 보기를 켜면**: 접이식 2개 열림 · 모든 영역 펼침 · 가장 낮은 순위 영역의 첫 평가항목이 선택되어 세부항목 패널이 열림. 끄면 선택된 항목이 해제됩니다.

### 9.5 AI 대화 패널 (오른쪽 · 모든 화면 공통)

**범위**: 화면(디자인)과 열고 닫는 동작, 대화 화면까지 만듭니다. **LLM을 호출하는 코드는 만들지 않습니다.** 사내 LLM API는 사용자가 따로 받아 연결하므로, 아래 5번의 **연결 자리**만 둡니다.

**1. 화살표 손잡이 `#chat-handle`**
- 화면 오른쪽 가장자리, 세로 가운데에 붙은 작은 탭(폭 30 · 높이 92, **왼쪽만 둥근 모서리**, 흰 면·옅은 테두리·왼쪽으로 번지는 그림자). 안에 위쪽 ✦(AI 아이콘, 파랑) + 아래쪽 화살표 `‹`.
- 누르면 패널이 **오른쪽에서 슬라이드**(0.22초)로 열리고, 손잡이는 **패널의 왼쪽 모서리에 붙어 함께 이동**하며 화살표가 `›`로 돌아섭니다(180° 회전). 다시 누르면 닫힘.
- `aria-controls="chat-panel"` · `aria-expanded` · `aria-label` 「AI 대화 열기」/「AI 대화 닫기」 · `title` 「AI 대화」. 마우스를 올리면 바탕이 `--surface-2`로.

**2. 패널 `#chat-panel`** (폭 380px, 화면 전체 높이, 왼쪽 테두리 + 그림자, `role="complementary"` · `aria-label` 「AI 대화」)
- 닫혀 있을 때: `visibility:hidden`(키보드로 못 들어감) + `aria-hidden="true"`. 열릴 때 즉시 보이게.
- **머리**: ✦ 아이콘 상자(30px, 연한 파랑) + 제목 「AI 어시스턴트」(`#chat-name`, 굵게) + 작은 글씨 「현재 화면 기준으로 질문해요」(길면 말줄임) / 배지 「API 미연결」(주황, `#chat-status`, 연결되면 숨김) / 아이콘 버튼 `＋`(`#chat-new`, 「새 대화」) · `›`(`#chat-close`, 「AI 대화 닫기」)
- **화면 정보 줄 `#chat-ctx`**: 칩 「현재 화면 포함」(켬/끔 토글, `aria-pressed`, **켜면 진한 바탕(`--ink`)에 밝은 글자**, 기본 켬, `title` 「켜면 현재 화면 정보를 질문과 함께 보냅니다」) + 글 「{화면 이름} · {필터 요약} · {n}개사[ · 선택: {협력사명 또는 영역명(코드 없이 이름만)}]」(`{필터 요약}`은 필터 줄의 「적용 중」 문구와 같은 규칙: `라벨 값`을 ` · `로 잇고 없으면 「전체」). 한 줄 말줄임, 마우스를 올리면 전체 글이 `title`로. 끄면 글이 「화면 정보를 보내지 않음」으로 바뀝니다.
- **대화 영역 `#chat-log`**(세로 스크롤, 새 메시지가 생기면 맨 아래로)
  - **빈 상태**: 가운데 큰 ✦ 아이콘 상자(46px) + 「무엇을 도와드릴까요?」(16px 굵게) + 회색 「화면의 결과를 바탕으로 질문해 보세요.」 + **추천 질문 버튼**(한 줄에 하나, 말풍선 아이콘 + 글, 누르면 **바로 전송**). 추천 질문은 화면에 따라 달라집니다.
    - 결과 요약(기본): 「이번 결과를 3줄로 요약해줘」「등급이 하락한 협력사의 공통점은?」「부진사 목록과 원인을 정리해줘」「전년 대비 가장 좋아진 업종은?」
    - 항목별 결과: 「{영역명(코드)} 영역 점수가 낮은 이유가 뭘까?」「{영역명(코드)}에서 먼저 개선할 평가항목은?」「전년 대비 가장 좋아진 영역은 어디야?」
    - 협력사별 결과: 「{협력사명} 결과를 3줄로 요약해줘」「{협력사명}의 약점 영역과 개선 방향은?」「{협력사명}의 5개년 추이를 설명해줘」
  - **내 말풍선**: 오른쪽 정렬, 바탕 `--chat-user`(#1c5cab), 흰 글자, 반지름 14px(오른쪽 아래만 4px), 줄바꿈 그대로(`pre-wrap`), 최대 폭 88%, 아래 작은 시각 `HH:MM`.
  - **AI 말풍선**: 왼쪽 ✦ 아바타(26px 원, 연한 파랑) + 말풍선(바탕 `--surface-2`, 옅은 테두리, 반지름 14px(왼쪽 위만 4px)), 아래 줄 「시각 · [주황 배지 「데모 응답」(데모일 때만)] · 복사」. 「복사」를 누르면 답변 글자를 클립보드에 넣고 1.2초 동안 「복사됨」.
  - **답변 글자 표시**: 간이 마크다운만 — `**굵게**`, `` `코드` ``, `- `·`* `·`• ` 목록, `1. ` 번호 목록, 빈 줄 무시, 나머지는 문단. **HTML은 해석하지 않고 글자 그대로** 보여 줍니다(`innerHTML` 금지, DOM으로 만들기).
  - **입력 중 표시**: AI 말풍선 안에 점 3개가 차례로 깜빡임(0.15초 간격, `role="status"`, `aria-label` 「답변 작성 중」). `prefers-reduced-motion`이면 정지.
  - **오류**: 옅은 빨간 말풍선 「답변을 가져오지 못했습니다. 잠시 후 다시 시도해 주세요.」 + 「다시 시도」(같은 질문을 다시 보냄)
- **입력줄**: 둥근 상자(바탕 `--surface-2`, 포커스 때 파란 테두리+연한 파란 링) 안에 `textarea#chat-input`(1~5줄 자동 늘어남, 최대 120px, 자리표시 「질문을 입력하세요 · Enter로 전송」, `title` 「Enter: 전송 · Shift+Enter: 줄바꿈」, `aria-label` 「질문 입력」) + 보내기 버튼 `#chat-send`(34px 둥근 사각, 파랑, ↑ 아이콘, `aria-label` 「보내기」, 입력이 비었거나 답변 대기 중이면 비활성). 상자 아래 작은 회색 글 「AI 답변은 부정확할 수 있습니다. 중요한 수치는 화면에서 확인하세요.」
- 스크린리더용 숨김 영역 `#chat-live`(`role="status"`, `aria-live="polite"`): 답변이 도착하면 그 글자를 넣어 읽게 함.

**3. 동작**
- 손잡이 / `›` 닫기 버튼 / 패널 안에서 `Esc`로 열고 닫음. 열면 입력칸에 포커스, 닫으면 포커스가 패널 안에 있었을 때 손잡이로 돌려줌.
- **Enter = 전송, Shift+Enter = 줄바꿈. 한글 입력 조합 중 Enter(`event.isComposing`, `keyCode 229`)는 전송하지 않습니다.**
- 전송: 내 말풍선 추가 → 입력칸 비움 → 입력 중 표시 → 답변이 오면 그 자리를 답변으로 교체. 답변 대기 중에는 새 전송 불가.
- `새 대화`: 기록 삭제 후 빈 상태로. **답변을 기다리는 중에 눌렀다면, 나중에 도착한 답변은 버립니다**(대화 번호로 구분).
- 대화 기록은 **메모리에만** 둡니다(화면을 옮겨도 유지, 새로 고침하면 사라짐, 저장 금지).
- 화면 정보 줄과(대화가 비어 있을 때) 추천 질문은 **화면이 모두 그려진 뒤에** 다시 그립니다(처음 들어간 화면의 기본 선택 영역·선택 협력사가 그려지는 중에 정해지기 때문).

**4. 배치 (반응형)**
- 화면 폭 **≥ 1480px**: 패널이 열리면 본문을 **옆으로 밀어냅니다**(`.app`에 `padding-right: 패널 폭`, 0.22초). 본문이 좁아진 만큼 반응형 기준을 **+380px** 올려 적용합니다: `1480~1699px` → KPI 3열(핵심 카드는 3열 폭)·영역 타일 4열, `1480~1559px` → 추가로 `span-3/4/5`는 6칸·`span-6/7/8`은 12칸·협력사 상세 머리 1열·기본 정보 3열.
- 화면 폭 **< 1480px**: 패널이 본문 **위에 겹쳐서** 열립니다(본문 폭 변화 없음).
- **≤ 760px(모바일)**: 패널은 화면 전체 폭. 닫힌 상태의 손잡이는 **오른쪽 아래 둥근 버튼**(48px, 파랑 바탕, 흰 ✦ 아이콘, 오른쪽·아래 16px)으로 바뀌고, 열리면 손잡이는 숨깁니다(머리의 `›`로 닫음).
- 인쇄: 패널·손잡이 숨김. `prefers-reduced-motion`: 슬라이드·점 애니메이션 끔.
- 층: 툴팁 50 > 손잡이 41 > 패널 40 > 모바일 상단 메뉴 20.

**5. 사내 API 연결 자리 (구현하지 말고 자리만)**
```js
// 앱 스크립트보다 먼저 한 번만 정의 (사용자가 사내 API를 받아 연결)
window.SUPPLIER_CHAT = {
  name: '사내 AI',                                                  // (선택) 패널 제목
  ask: async ({ message, history, context }) => '답변'               // 문자열 또는 { text: '답변' }
};
```
- `history`: 이번 질문 앞의 대화 `[{ role: 'user' | 'assistant', text }]` — 최근 20개, 오류 답변 제외
- `context`: 「현재 화면 포함」이 꺼져 있으면 `null`, 켜져 있으면 아래 모양(**필요한 만큼만** — 협력사 상세 값을 더 담지 않음)
  `{ screen: '결과 요약', hash: '#report', year: 2026, filters: { 필터라벨: 값 }, count: 1248, detail: false, summary?: { avgDtScore: 82.9, grades: { A, B, C, D } }, selected?: { type: '협력사' | '영역', code, name, grade?, dtScore? } }` — `summary`는 협력사가 1곳 이상일 때만, `selected`는 협력사별 결과에서 협력사가 선택됐을 때(`grade`·`dtScore` 포함)와 항목별 결과에서 영역이 선택됐을 때(`code`·`name`만)만 넣습니다. 등급 개수는 `CONFIG.grades` 순서.
- 연결되어 있으면 「API 미연결」 배지를 숨기고 `name`을 제목으로 씁니다. `ask`가 예외를 던지거나 빈 답변을 주면 오류 말풍선.
- **연결 전(데모)**: 약 0.75초 뒤 아래 4줄 답변(줄바꿈 그대로)을 보여 주고 배지 「데모 응답」을 붙입니다. 「화면 정보 포함」이 꺼져 있으면 마지막 줄이 「없음」.
```text
**사내 API가 아직 연결되지 않았습니다.**
연결하면 이 자리에 답변이 표시됩니다.
- 질문: {내 질문}
- 함께 보낼 화면 정보: {화면 이름} · {필터 요약} · {n}개사
```
- **배치**: `dist/index.html`의 `app.js` **앞**에 **주석 처리된** `<!-- <script src="chat-adapter.js"></script> -->` 한 줄과 「사내 API 연결 시 주석을 풀고 chat-adapter.js를 만드세요」 설명을 둡니다(파일이 없는 채로 불러오면 콘솔 오류가 나므로 연결할 때 풉니다). `src/chat-adapter.example.js`는 위 `window.SUPPLIER_CHAT` 모양의 **뼈대만** 담고(`ask`는 「사내 API 연결 필요」 오류를 던짐) 주소·키·호출 코드는 없습니다. 실제 `dist/chat-adapter.js`는 `.gitignore` 대상(사내 주소가 들어갈 수 있음).
- **서버로 올린 뒤**: `chat-adapter.js`의 `ask`는 **같은 서버의 중계 주소**(상대 경로, 예: `api/chat`)만 부르고, 사내 LLM 주소·키는 **서버에만** 둡니다(브라우저 코드에 키·토큰 금지 — 키 노출·CORS 방지). 중계 서버는 이 프로젝트의 범위가 아닙니다. 로컬에서 `file://`로 열면 `fetch`가 막힐 수 있으니 어댑터는 `python -m http.server`로 열어 시험합니다.
- **금지**: LLM 주소·키·토큰·호출 코드를 프로젝트에 넣지 않습니다. 대화 내용과 화면 정보는 `ask`로만 나갑니다(그 이후의 보안은 API 연결하는 쪽 책임).

**설정**(`settings.chat`, §11): `{ enabled: true, name: 'AI 어시스턴트', history: 20 }` — 패널 제목 = `window.SUPPLIER_CHAT.name`이 있으면 그것, 없으면 `settings.chat.name`. `enabled: false`이면 패널·손잡이를 만들지 않습니다. 패널 폭(380px)과 밀어내기 기준(1480px)은 CSS 값입니다(부록 A).

## 10. 공통 동작

1. **라우팅**: 해시 `#report`(기본) · `#area` · `#company`. 해시가 없거나 틀리면 `#report`. 화면이 바뀌면 맨 위로 스크롤하고 메뉴 강조·제목·탭 제목·`lead`를 갱신합니다. 각 화면은 **처음 열 때 한 번 틀을 만들고**(`build`), 이후에는 값만 다시 그립니다(`render`).
2. **필터**(7개): ① `평가 연도` = 기준연도 변경(5개년 다시 계산, 선택지는 ①②③④가 모두 있는 연도만 — §6.9) ② `평가조직` = **그 조직의 평가 행이 있는 협력사**(`evals`에 포함) ③ `권역명` ④ `내/외자` ⑤ `평가단위` ⑥ `세부업종그룹` ⑦ `D/T 최종 등급` = 올해 최종 등급이 같은 협력사. 여러 개는 **AND**. 바꾸면 현재 화면 전체가 같은 `L`로 즉시 다시 계산됩니다. 등급 필터를 뺀 필터가 바뀌면 `항목별 결과`의 영역 선택은 초기화됩니다.
3. **상세 보기**: `body`에 `show-detail` 클래스를 토글하고(`상세에서만` 카드가 보임) 현재 화면을 다시 그립니다. 켜짐 상태 글자 「상세 보기 켜짐」, `aria-pressed`. 화면을 옮겨도 유지됩니다.
4. **테마**: 기본 라이트. `다크 모드` 버튼으로 전환, 선택은 `localStorage`(`supplier-dash-theme`)에 저장(저장이 막혀도 동작해야 하므로 `try/catch`). 전환하면 CSS 변수와 JS 팔레트를 함께 바꾸고 차트를 다시 그립니다.
5. **툴팁**: 막대·점·칸·타일·행마다 마우스 올림과 키보드 포커스에서 같은 내용. 모든 툴팁 값은 표 보기·직접 라벨로도 확인할 수 있어야 합니다(툴팁이 유일한 경로가 되면 안 됨). 작은 점은 눈에 보이는 크기보다 넓은 클릭/호버 영역(약 24px)을 줍니다.
6. **표 보기**: `표` 카드는 차트와 같은 숫자를 표로 보여 줍니다(§9에 열이 적혀 있음).
7. **CSV**: 파란 작은 버튼 「내려받기」 계열. UTF-8 BOM, `\r\n`, 파일 이름은 §9에 적힌 그대로. 줄은 **화면에 보이는 개수가 아니라 해당 전체 집합**(예: 70점 미만 전체, 정렬·칩·검색이 적용된 전체 목록).
8. **인쇄**(`결과 요약`의 「인쇄 · PDF 저장」, 브라우저 인쇄도 동일): A4, 여백 12mm, 흰 바탕. 인쇄 때 **숨김**: 왼쪽 메뉴, 상단 막대, 필터 줄, 적용 중 필터 줄, `.no-print`, 카드의 도구(`표` 버튼 등), `i` 버튼, 카드 하단의 버튼·링크, 툴팁. **바꿈**: 본문 한 열(모든 카드 12칸), 카드·KPI는 쪽 중간에서 잘리지 않게(`break-inside: avoid`), 펼침 표의 평가항목 줄은 **모두 펼쳐서** 출력, 카드 그림자 제거.
9. **반응형**: §8.3. 창 폭이 바뀌면(`ResizeObserver`, 120ms 지연) 차트를 다시 그립니다(SVG 폭을 컨테이너에 맞춤, 최소 폭 있음).
10. **접근성**: 키보드로 모든 기능 사용(Tab 이동, Enter 실행), 포커스 링(2px 파랑, 오프셋 2px), `aria-pressed`(칩·타일·토글), `aria-expanded`(펼침 행), `aria-current="page"`(메뉴), `aria-label`(차트·마크·타일 — 아래 목록), 표 머리글, 색 외 정보(▲▼, 글자) 병행. `prefers-reduced-motion`에서는 부드러운 스크롤을 끕니다.
    - `aria-label` 목록: 메뉴 「화면」 · 필터 줄 「필터 (모든 화면에 적용)」 · 영역 타일 묶음 「영역 선택」 · 칩 묶음 「상태로 거르기」 · 검색 「협력사 검색」 · 정렬 「정렬」 · 페이지 버튼 「이전 페이지」「다음 페이지」 · 적용 중 필터 칩 「{라벨} {값} 필터 해제」 · 차트(`role="img"`) 「{이름} 5개년 {연도} {값}, …」 · 분할 막대 「{행} 등급 구성 A {비율}, B …」 · 막대·점·칸 = 툴팁 내용 그대로
11. **성능**: 협력사 5,000개 이하에서 필터 변경 후 화면 갱신이 체감 1초 이내. 표는 한 번에 10행만 그리고, 순위·평균은 렌더 한 번에 한 번만 계산(캐시)합니다. 입력 검색은 180ms 지연.

## 11. 설정 파일 `config/settings.js`

사내 기준값은 **이 파일만 고치면** 되게 만듭니다. 화면 코드에 숫자·이름을 박지 않습니다.

```js
window.SUPPLIER_SETTINGS = {
  baseYear: null,                 // null = 엑셀 폴더 아래 ①②③④가 모두 있는 가장 큰 연도
  yearsBack: 4,                   // 5개년 = 기준연도−4 … 기준연도
  asOf: null,                     // 기준일 'YYYY-MM-DD' (null = 가장 최근 엑셀 파일 수정일)
  sourceLabel: '사내 엑셀 4종',
  data: { url: null },            // null = data.js(<script>)로 읽음. 서버에서 JSON으로 읽으려면 'data.json' 같은 상대 주소(§5.1)

  // ── 등급 (확정) ──
  grades: ['A', 'B', 'C', 'D'],                                   // 높은 등급 → 낮은 등급
  gradeCut: { A: 90, B: 80, C: 60 },                              // 점수 이상(≥), 그 외 D
  gradeLabel: { A: '우수', B: '양호', C: '개선 필요', D: '부진' },   // ※ 임시 — 사내 용어로 교체

  // ── 영역 (※ 이름은 임시) ──
  areas: [
    { code: 'T', name: '기술' }, { code: 'Q', name: '품질' }, { code: 'R', name: '대응' }, { code: 'D', name: '납기' },
    { code: 'C', name: '원가' }, { code: 'E', name: '환경' }, { code: 'F', name: '재무' }, { code: 'A', name: '기타' },
  ],
  classToArea: {},                // 분류체계 값 → 영역 코드. 비우면 값이 영역 코드(T/Q/R/D/C/E/F/A)일 때만 인정

  // ── 기준·표시 값 (※ 임시) ──
  targets: { avgScore: 85 },      // 목표 평균 점수
  lowLine: 70,                    // 영역 '약함' 기준 점수
  nearA: 5,                       // A 승급 후보 = A 기준 아래 5점
  topN:  { core: 5, detail: 10 }, // 상승/하락 TOP 개수 (핵심 / 상세 보기)
  listN: { core: 5, detail: 20 }, // 부진사·우수사 목록 개수
  pageSize: 10,                   // 협력사 목록 쪽당 행 수
  chat: { enabled: true, name: 'AI 어시스턴트', history: 20 },   // AI 대화 패널(§9.5) — 제목은 window.SUPPLIER_CHAT.name 이 우선, history = ask 에 넘기는 이전 대화 개수

  // ── 부진사 · 우수사 후보 (※ 임시 기준 — 확정되면 rules만 교체하고 fixed: true) ──
  criteria: {
    poor: { name: '부진사', fixed: false, mode: 'any', rules: [          // any = 하나라도 해당
      { label: 'D등급 (60점 미만)',       when: { field: 'grade', op: 'in', value: ['D'] } },
      { label: '전년 대비 2단계 이상 하락', when: { field: 'move', op: '<=', value: -2 } },
    ] },
    excellent: { name: '우수사 후보', fixed: false, mode: 'all', rules: [  // all = 모두 해당
      { label: 'A등급 (90점 이상)',         when: { field: 'grade', op: 'in', value: ['A'] } },
      { label: '전년 대비 등급 하락 없음',   when: { field: 'move', op: '>=', value: 0, nullPass: true } },
      { label: '등급 조정·거래중단 예정 아님', when: [ { field: 'adjTarget', op: '==', value: false }, { field: 'stopPlan', op: 'empty' } ] },
    ] },
  },
  // when 문법: field = grade | prevGrade | move | dtScore | prevDtScore | dtChange | adjTarget | stopPlan
  //                    | area.<영역코드> | group | org | inout | region

  // ── 엑셀 컬럼 이름(동의어 목록) — 사내 표기가 다르면 여기에 추가 (기본값은 부록 C의 COLUMNS) ──
  columns: { /* 파일 종류별 { 모델필드: ['이름', '동의어', …] } */ },
};
```

- **형식**: `config/settings.js`는 **일반 스크립트**(`window.SUPPLIER_SETTINGS = {…};`)입니다. `export`·`import` 금지(`file://`에서 ES 모듈이 막힘). 값은 문자·숫자·불리언·null·배열·객체만 쓰고(함수·정규식·날짜 객체 금지) 주석은 허용합니다. **브라우저와 빌드 도구가 같은 파일을 읽습니다**: 브라우저는 `<script src="settings.js">`(빌드가 `dist/`로 복사), 빌드 도구는 엑셀 변환에 필요한 값(`baseYear` `yearsBack` `asOf` `sourceLabel` `classToArea` `columns` `areas` 등)을 읽습니다. 파이썬 빌드는 `tools/read_settings.py`가 `window.SUPPLIER_SETTINGS =` 뒤의 객체를 JSON으로 바꿔 읽고(주석 제거 · 따옴표 없는 키와 작은따옴표 문자열을 JSON으로 · 끝 쉼표 제거, 문자열 안의 `//`와 `'`는 건드리지 않도록 **문자 단위**로 처리), Node 빌드는 그대로 실행해 읽습니다. 단위 테스트(§13.1-9)로 고정합니다.
- 설정을 읽는 곳은 **한 모듈**(`config.js`)로 모읍니다. `gradeOf`, 등급 이름표, 영역 이름(`영역명(코드)` 표기), 기준선 라벨(「목표 85」, 「A 기준 90」), 기준 줄 문구는 모두 설정에서 만듭니다.
- `fixed: false`인 기준에는 화면에 `임시 기준` 배지·문구가 붙습니다(§9). `fixed: true`로 바꾸면 `확정 기준`.

## 12. 샘플 모드와 골든 값 (개발·검증용)

- **샘플 모드** = 실제 엑셀 없이 가상 데이터로 전 화면을 띄우는 모드. **주소에 `?sample=1`이 있을 때만** 켜집니다(`dist/data.js`가 없다고 자동으로 켜지지 않음 — 서버에서 데이터 파일이 빠졌을 때 가짜 데이터가 진짜처럼 보이는 사고를 막기 위해, §5.1). 사이드바에는 「데이터: 가상 샘플 (목업)」이 표시됩니다. `?sample=1&points=N`(N=2~5)이면 5개년 추이에 **최근 N개 점만** 남깁니다(`points=2` = 기준연도 1개년만 넣은 엑셀과 같은 화면 — §6.9의 부분 연도 화면 확인용).
- 샘플 생성기는 **부록 E**(난수 시드 `20261109`, 협력사 1,248개, 5개년 이력 시드 `5150`)를 **호출 순서까지 그대로** 이식합니다. 그러면 부록 F의 **골든 값**(평균, 등급 개수, 칩 개수, TOP 협력사 이름 등)이 똑같이 나옵니다.
- 골든 값은 **왕복 검증**(§4 M7-3)과 **회귀 테스트**에 씁니다: 샘플 → (엑셀 4종 × 5개년) → `build_data` → 화면이 같은 숫자를 내는지.
- 개발 중 화면 비교는 목업(`종합평가_대시보드_목업.html`)을 옆 창에 띄워 나란히 봅니다.

## 13. 검증 체크리스트 (M9에서 전부 실행)

### 13.1 자동 테스트 (단위)
1. `gradeOf`: 100→A, 90→A, 89.9→B, 80→B, 79.9→C, 60→C, 59.9→D, 0→D
2. `fmt`: `pct(7.1)`=7.1%, `pct(9)`=9%, `pct(16.9)`=17%, `pct(0.4)`=0.4%, `sgn(0)`=±0.0, `sgn(-1.26)`=−1.3
3. `delta`: 0.04→`– 0.0`(회색), `goodUp=false`에서 음수→파랑
4. `ranker`: 동점 같은 순위, null 제외, `rankText` 경계(상위 50% / 하위)
5. `critPass`: `any`/`all`/`nullPass`/`empty` 동작, 임시 기준 두 개가 부록 F 개수와 일치
6. 집계: `areaAvg`, `yearAvg`, `yShare`, `itemStats`(미적용·무실적 제외)
7. **골든 값 일치**(부록 F)
