# 협력사 종합평가 대시보드 — 구현 명세 (opencode 전달용)

## 0. 목적
협력사 종합평가 결과를 4개 엑셀 원장으로부터 읽어, 요약 → 협력사 → 영역 → 평가항목 → 세부항목 순으로 드릴다운하는 대시보드를 만든다.
실제 데이터는 사내 정보이므로 **코드에 포함하지 않는다.** 엑셀 업로드(또는 사내 지정 경로) 방식으로 로드하고, 개발·테스트는 가상 샘플 데이터 생성기로 한다.

## 1. 데이터 소스 (엑셀 4종)
헤더는 2단(그룹행 + 컬럼행)이며, 그룹행은 병합 셀이다. 파싱 시 그룹행을 컬럼명 접두사로 합치거나(예: `평가결과.배점`, `전년도 결과.배점`) 위치로 구분한다. 1번 파일은 "배점/일반항목 평점/…" 컬럼이 당해·전년도에 중복되므로 반드시 그룹으로 구분한다.

| 파일 | 이름(가칭) | 행 단위 | 핵심 컬럼 |
|---|---|---|---|
| 1 | 평가결과 요약 | 협력사 × 세부평가단위 | D/T 코드, 협력사 코드/명, 협력사 확인, 평가조직, 권역 코드/명, 내/외자, 평가단위, 세부 평가단위 코드/명, 세부업종그룹 / (당해) 배점, 일반항목 평점, 일반항목 환산점수, 가산점, 평가 점수, 점수 변동, D/T 종합 점수, D/T 최종 등급 / (전년도) 배점, 일반항목 평점, 일반항목 환산점수, 가산점, 평가 점수, D/T 종합 점수, D/T 최종 등급 |
| 2 | G/T 상세 | 협력사 × 평가조직 | 일반 조직, 평가조직, G/T 코드, D/T 코드, 협력사 코드/명, 권역, 국가, 내/외자, 업종, 세부 평가단위, 주거래, 대표코드, 기업 규모, 금형, 거래중단예정일, 거래중단일, 배점, 일반항목 평점/환산점수, 가산점, 평가 점수, 평가조직 등급, D/T 종합 점수, D/T 등급 반영비중-거래비중, D/T 거래비중별 개별합계/총합계, D/T 조정 전 등급, 등급 조정 대상, D/T 최종 등급, D/T 전년도 등급, G/T 종합 점수, G/T 등급, 영역 T·Q·R·D·C·E·F·A 각각 (배점, 평점, 환산점수, 배점(비중), 평점(비중)), G/T 등급 반영비중-거래비중 |

| 4 | 세부항목 상세 | 평가항목 × 세부항목 | D/T 코드, 협력사 코드/명, 평가조직, 평가단위, 세부 평가단위 코드/명, 평가항목 코드/명, 세부 등록 주체, 배점, 평점, 환산 평점, 세부항목 코드/명, 세부항목 값 |

### 1.1 조인 키 (가정, 사내 확인 필요)
- 1 ↔ 2: `D/T 코드 + 협력사 코드 (+ 평가조직 + 세부 평가단위 코드)`
- 2/1 ↔ 3: `D/T 코드 + 협력사 코드 + 평가조직 + 세부 평가단위 코드`
- 3 ↔ 4: 위 키 + `평가항목 코드`
- 조인 키는 설정 파일로 분리해 사내에서 쉽게 수정할 수 있게 한다.

### 1.2 계층 및 등급 흐름
`평가항목 → (영역 T/Q/R/D/C/E/F/A) → 평가조직 등급 → (거래비중 가중) D/T 종합 점수 → 조정 전 등급 → 등급 조정 → D/T 최종 등급 → G/T 종합 점수/등급`

## 2. 데이터 처리 규칙
- 숫자 컬럼은 문자열·공백·`-`를 NaN으로 안전 변환한다.
- `미적용 여부`, `무실적 여부` = Y인 항목은 득점률·평균 계산에서 제외하고 별도 건수로 집계한다.
- **등급 체계(확정)**: 점수 90 이상 **A**, 80 이상 **B**, 60 이상 **C**, 60 미만 **D** (A>B>C>D). 등급 상승/하락은 이 순서로 판정한다.
  - 구간은 설정 한 곳(`GRADE_CUT`)에서 바꿀 수 있어야 한다. 경계값 처리: 90.0 → A, 89.9 → B, 80.0 → B, 79.9 → C, 60.0 → C, 59.9 → D
  - 평가조직 등급, D/T 조정 전·최종 등급, G/T 등급에 같은 구간을 적용한다(가정). 엑셀에 등급 값이 있으면 그 값을 우선 사용하고, 없을 때만 점수로 계산한다.
  - 등급 이름표(A 우수 · B 양호 · C 개선 필요 · D 부진)는 임시 — 사내 용어로 교체(`CONFIG.gradeGroup`)
- 득점률 = 환산점수 / 배점(0 나눗셈 방어).
- 전년 대비 = 당해 − 전년도(점수), 등급 순서 비교(등급).
- 거래중단 예정/중단 협력사는 플래그로 표시한다.
- 데이터 로드는 서버 메모리에서만 처리하고 외부로 전송하지 않는다.

## 3. 화면 구성

### 3.1 공통 필터 (전 화면 연동)
평가조직, 권역, 내/외자, 평가단위, 세부 평가단위, 세부업종그룹, 업종, 기업 규모, 주거래, 금형, 등급, 거래중단 여부, 협력사명 검색.

### 3.2 ① 종합 현황
- KPI 카드: 평가 대상 협력사 수, 평균 평가 점수, 전년 대비 평균 변동, 등급 상승/하락 협력사 수, 등급 조정 대상 수, 거래중단 예정 수
- 최종 등급 분포(막대) + 전년 대비 분포 비교
- 권역별·평가조직별 평균 점수
- 점수 분포 히스토그램

### 3.3 ② 전년 대비 변동
- 점수 변동 상위/하위 N개 협력사
- 등급 이동 매트릭스(전년 등급 × 당해 등급 히트맵)
- 상승/하락 협력사 목록

### 3.4 ③ 협력사 상세
- 헤더: 협력사 정보(코드, 권역, 국가, 업종, 규모, 거래중단 여부)와 D/T·G/T 등급 및 점수
- 영역 레이더 차트(T/Q/R/D/C/E/F/A, 득점률)와 평가조직별 비교 오버레이
- 평가조직별 등급 표와 거래비중, 조정 전/후 등급
- 평가항목 테이블(득점률, 환산평점 변동, 미적용/무실적 표시)
- 항목 클릭 시 세부항목 패널(4번 데이터) 표시

### 3.5 ④ 영역/항목 분석
- 영역별 평균 득점률 비교(전체 및 필터 기준)
- 평가항목별 평균 득점률 하위 N개(공통 취약 항목)
- 환산평점 변동이 큰 항목 TOP/BOTTOM
- 미적용/무실적 항목 현황

### 3.6 ⑤ 등급 조정/주의 목록
- 등급 조정 대상 목록(조정 전 → 조정 후)
- 거래중단 예정 협력사
- 주의 협력사(저등급 + 하락 + 점수 하위)

모든 표는 정렬, 검색, 엑셀 내보내기를 지원한다.

## 4. 비기능
- 한국어 UI, 숫자 천단위/소수점 1~2자리 통일
- 대용량(수만~수십만 행) 대비: 집계는 사전 계산, 표는 가상 스크롤/페이지네이션
- 컬럼명·등급 체계·조인 키·영역 매핑은 `config`로 분리(사내 환경 맞춤)
- 가상 샘플 데이터 생성 스크립트 포함(4개 파일 동일 구조)
- 스택은 사내 opencode 환경에 맞춰 선택

## 5. 사내 확인 필요 사항 (기본값으로 구현 후 config로 조정)
1. 협력사 확인, D/T, G/T의 의미와 계층(G/T ⊃ D/T 가정)
2. ~~등급 체계와 구간 기준~~ → 확정: A 90점 이상, B 80점 이상, C 60점 이상, D 60점 미만 (등급 이름표만 사내 용어로 교체)
3. 분류체계 값과 영역 T/Q/R/D/C/E/F/A의 대응 및 약어 풀이
4. 1~4번 파일 간 정확한 조인 키
5. 평가 주기(월/분기/연)와 다중 기간 파일 지원 여부

## 6. 화면 목업 (v3)
- 파일: `docs/종합평가_대시보드_목업.html` (단일 HTML, 외부 라이브러리 없음, 가상 샘플 데이터)
- 화면 3개(좌측 메뉴): **결과 요약**(첫 화면) / **항목별 결과** / **협력사별 결과** · 공통 필터 1줄 + 적용 중 필터 칩
- **핵심 먼저, 상세는 필요할 때**: 기본은 핵심만 표시. 상단 `상세 보기`를 켜면 세부 카드·표가 함께 펼쳐짐
  (영역→평가항목 펼침, 상위·하위 10개, 부진사·우수사 20개, 업종(세부)·평가조직별 결과, 평가항목 상세표, 업종그룹별 점수, 등급 산출 근거)
- 엑셀 컬럼 ↔ 화면 필드 매핑: 스크립트의 `COLUMNS`, 기준값(등급 구간·영역명/배점·목표·부진사/우수사 기준): `CONFIG`
- 각 카드 제목 옆 (i)에 마우스를 올리면 그 카드가 쓰는 엑셀 컬럼명 표시

### 6.2 항목별 결과
- 영역 카드 8개: 점수 · 전년 대비 · 5개년 추이선 · 평균 대비 상태 (누르면 선택, 기본 = 가장 낮은 영역)
- 선택 영역: 5개년 추이(전체 영역 평균과 비교) · 평가항목별 점수(영역 평균선) · 하위 협력사 5 (+70점 미만 명단 CSV)
- 상세 보기: 평가항목 상세표(유형·배점·70점 미만 비율·미적용·무실적) · 업종그룹별 점수

### 6.3 협력사별 결과
- 목록: 검색, 상태 칩(전체·상승·하락·2단계 하락·부진사·우수사 후보·A 승급 후보(85~89.9점)·C·D·조정·거래중단), 정렬, 페이지, 5개년 추이선, CSV
- 상세: 한 줄 결론(등급·순위·순위가 가장 높은/낮은 항목) + 점수·등급(올해/전년/G/T)·전체 순위
- **5개년 추이**: 협력사 점수 vs 전체 평균, 점 위에 그해 등급, A 기준선 · 표 보기에서 그해 순위
- **항목별 점수와 순위**: 영역별 점수 · 전체 평균 · 순위(○위, 상위/하위 %) · 전년 대비 · 5개년 추이선 → 영역을 누르면 평가항목 순위 → 평가항목을 누르면 세부항목(4번 파일)
- 접어 둔 정보: 등급 산출 근거(평가조직별 점수·거래비중·조정), 기본 정보(코드·조직)
- 순위 기준: 필터 적용 범위 안에서 높은 점수 순 (상위 20% 파랑, 하위 20% 빨강)

### 6.4 5개년 데이터
- 연도별 1·2번 파일(5년치)을 쌓아 `x.hist[연도] = { dt, grade, areas }` 구조로 채움 (2025 = [전년도 결과], 2026 = [평가결과])
- 그 해 평가가 없던 협력사(신규)는 빈 값으로 두고 추이선에서 끊어 표시
- 목업의 2022~2024 값은 가상 데이터

| 기준값 표시 | 목표선 · A 기준선(점선), 전체/영역 평균, 전년도 비교 |
| "그래서?" | 결론 문장, 최고·최저 순위 표시, 다음 행동 링크(명단 보기 · CSV) |
| 상세는 필요할 때 | 상세 보기 버튼, 영역 펼치기, 접어 둔 정보, 표 보기 |

### 6.6 목업에서 둔 해석 (사내 확인 후 수정)
- 배점 = 적용 항목 배점 합(미적용·무실적 제외), 평점 = 득점 합, 환산점수 = 평점 ÷ 배점 × 100
- 평가 점수 = 일반항목 환산점수 + 가산점, D/T 종합 점수 = Σ(평가조직별 평가 점수 × 거래비중)
- 3번 파일 분류체계 = 영역 코드(T~A), 분류체계 유형 = 정량/정성
- 영역명(기술·품질·대응·납기·원가·환경·재무·기타)은 TQRDC 관례로 둔 예시, 목표값(평균 80점 등)도 예시
- 부진사·우수사 후보 기준은 임시 (`CONFIG.criteria`의 rules만 교체하면 반영)
  - 임시 부진사: D등급(60점 미만) 또는 전년 대비 2단계 이상 하락 / 임시 우수사 후보: A등급(90점 이상) + 등급 하락 없음 + 조정·거래중단 아님
- 샘플 데이터는 새 등급 기준에 맞춰 평균 약 83점(A 약 17% · B 약 52% · C 약 30% · D 약 1%)으로 생성, 목표 평균 85점은 예시

### 6.7 AI 대화 패널 (오른쪽 · 모든 화면 공통)
- 화면 오른쪽 가장자리의 **화살표 손잡이**를 누르면 오른쪽에서 **대화 패널(폭 380px)**이 열리고, 다시 누르거나 `›`·`Esc`로 닫음. 화면 폭 ≥ 1480px에서는 본문을 옆으로 밀고, 그보다 좁으면 본문 위에 겹쳐서 열림. 모바일(≤ 760px)은 오른쪽 아래 둥근 버튼 + 전체 폭 패널. 인쇄에서는 숨김
- 구성: 머리(이름 · `API 미연결` 배지 · 새 대화 · 닫기) → `현재 화면 포함` 칩과 화면 정보 한 줄 → 대화 영역(빈 상태에서는 화면별 **추천 질문**) → 입력줄(Enter 전송 · Shift+Enter 줄바꿈 · 한글 조합 중 Enter 무시)
- **디자인과 열고 닫는 동작까지만 구현**: LLM 호출 코드는 없음. 사내 API는 `window.SUPPLIER_CHAT = { name, ask({ message, history, context }) }`를 앱 스크립트 앞에 정의해 연결(연결 전에는 데모 답변). 질문과 함께 보내는 화면 정보(`context`)는 화면 이름·필터·협력사 수·평균·등급 개수·선택 항목 정도로 최소화하며, `현재 화면 포함`을 끄면 보내지 않음
- 대화 기록은 메모리에만 보관(새로 고침하면 삭제), 답변은 안전한 간이 마크다운(굵게·코드·목록)으로만 표시(HTML 해석 없음)

### 6.8 배포와 데이터 제공 방식
- **지금은 로컬 → 나중에 서버**: 엑셀·화면 모두 로컬에서 시작하고, 나중에 `dist/` 폴더(정적 파일)를 서버에 올림. 경로는 상대 경로·명령줄 인자(`--data-dir` `--out`)로 받고, 서버 쪽 프로그램·로그인은 만들지 않음(서버에서 접근 제한). 데이터는 `data.js`로 읽고, 못 읽으면 **오류 화면**(샘플로 대체하지 않음). 샘플은 주소에 `?sample=1`일 때만
- **1개년 먼저 → 나머지는 나중에**: 기준연도 4종만으로 전 화면 + 전년 비교가 동작(추이는 2점). 과거 연도는 ①(점수·등급), 영역 추이는 ②까지만 필요하며 최근 연도부터 폴더를 추가하고 다시 빌드 — ③④는 기준연도만 필요. 격년(①만 기준·기준−2·기준−4)으로 줘도 점수·등급 5개년이 채워짐(`[전년도 결과]` 이용). 자료 없는 해는 그리지 않고 추이 카드에 「자료 n/5개년」 배지 표시
- 새 엑셀을 넣기 전에 `build_data --check <파일>`로 헤더·컬럼 매핑만 먼저 점검
- **올리는 곳 = 사내 GitHub**: 저장소에는 코드·문서만 올리고 데이터(엑셀·`data.js`·`dist/`·`build/`)는 올리지 않음(`.gitignore` + 커밋 전 점검 훅 `check_no_data`). 화면은 ① 각자 PC에서 clone → 엑셀 넣기 → build → 열기(기본) ② 사내 서버·공유 폴더에 `dist/` 복사 ③ (사내 보안 정책 확인 후에만) 사내 GitHub Pages 발행 — 발행 전용 브랜치에 이력 없이 덮어쓰기(M10, 선택). 원격 푸시는 사용자 확인 후
